2) Make Workfront honor sequencing (no more “everything starts on day 1”)

Root cause
Our XML only links some leaf subtasks to their immediate prior subtask. We never anchor whole groups to the previous group (or deliverable) and we don’t replicate the predecessor to sibling role‑rows. That’s why Workfront shows all top‑level activities in parallel.

Fix — three parts

(a) Add anchor tasks per deliverable

Create zero‑duration tasks [DELIV_X_START] and [DELIV_X_END] for every deliverable.

Link each [DELIV_X_START] FS to the previous deliverable’s [DELIV_(X−1)_END].

Link each first component inside the deliverable FS to [DELIV_X_START].

Link [DELIV_X_END] FS to the last real task within the deliverable.

This ensures the entire deliverable block can’t begin before the previous deliverable finishes, and gives Workfront a clean, explicit dependency chain at the deliverable level (not only leaves).

(b) Chain components (task groups) inside a deliverable

Inside each deliverable, take the ordered list of components (e.g., prepro_docs → prepro_coord → edit → client_review → packaging, etc.). For each component G:

Connect the first real row of G FS to the last real row of the previous component G-1 (or to [DELIV_X_START] if G is first).

Everything else in G inherits that same predecessor (see (c)).

(c) Replicate predecessor to all repeated rows in the same component

When one logical step (say edit) expands to many rows by role (Producer, Designer, Editor…), assign the same predecessor to every row in that step, not just the first instance. Also chain rows within the component if needed (simple previous‑row FS) to avoid same‑minute starts when you want serial effort.

The XML exports you shared show we currently only set PredecessorLink on a subset of sub‑rows and not on their siblings; many tasks therefore begin at the <Project><StartDate>…</StartDate> time (e.g., 2025‑10‑06 09:00).

Where to change this in code

In the FastAPI backend (file with app = FastAPI(...) and XML building code), locate the function that emits <Tasks> and <PredecessorLink> nodes (you already import xml.etree and build <Project>, <Resources>, <Tasks>, <Assignments>). Nearby you’ll see our Workfront export column map (includes Start_Offset_Days, Duration_Days, Dependencies) — that’s the right place to feed the new dependency graph.

Implement:

# Pseudocode inside the XML builder

uid = 0
def new_uid():
    nonlocal uid; uid += 1; return uid

prev_deliv_end_uid = None

for d in deliverables_in_scenario_order:  # order saved by Step 4 (the “Save Order” button)
    start_anchor = new_uid()
    add_task(uid=start_anchor, name=f"[{d.name}] START", duration=0, is_summary=False)

    if prev_deliv_end_uid:
        add_pred(task_uid=start_anchor, pred_uid=prev_deliv_end_uid, type='FS')

    last_of_prev_group = start_anchor

    for group in d.components_in_order:  # e.g., prepro_docs -> prepro_coord -> edit -> client_review -> packaging
        group_rows = rows_by_component[group]
        first_uid_in_group = None
        prev_row_uid = None

        for r in group_rows:                 # every role-slice row in this group
            row_uid = new_uid()
            add_task_from_row(row_uid, r)    # sets Start/Finish from offsets; duration in minutes

            # key: every row in this group inherits the predecessor from the last_of_prev_group
            if prev_row_uid:
                # optionally serialise within the group
                add_pred(task_uid=row_uid, pred_uid=prev_row_uid, type='FS')
            else:
                add_pred(task_uid=row_uid, pred_uid=last_of_prev_group, type='FS')

            prev_row_uid = row_uid
            if not first_uid_in_group:
                first_uid_in_group = row_uid

        last_of_prev_group = prev_row_uid  # last row of this component

    end_anchor = new_uid()
    add_task(uid=end_anchor, name=f"[{d.name}] END", duration=0, is_summary=False)
    add_pred(task_uid=end_anchor, pred_uid=last_of_prev_group, type='FS')

    prev_deliv_end_uid = end_anchor


Use <Type>1</Type> for FS in <PredecessorLink> (that’s what the exports currently use).

This single graph change fixes all three observations in your Slack notes:

tasks no longer all start at project start,

“everyone in Edit has the same (#14) predecessor” becomes true,

and successors/predecessors across components respect duration overlap only where we explicitly allow it.

If you later want chosen components to run in parallel, add a boolean (e.g., ParallelOK) in the DB for those components and skip the FS from G to G+1 for them; keep the deliverable start/end anchors so WF still understands where the block begins/ends.
