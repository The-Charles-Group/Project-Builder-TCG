3.2 When a component cell is edited

Goal: Every change in Deliverable Pricing Details updates window.SCENARIO_A in a way the backend understands.

The Replit agent said applyPricingEditToScenario() exists. It needs to be at least as strong as this (pseudo‑code):

function applyPricingEditToScenario(deliverableCode, componentLabel, newHours) {
  const scen = window.SCENARIO_A;
  if (!scen || !Array.isArray(scen.items)) return;

  const d = scen.items.find(
    item => item.Deliverable_Code === deliverableCode ||
            item.deliverable_code === deliverableCode
  );
  if (!d) return;

  // 1) Ensure component_hours map exists on the deliverable
  if (!d.component_hours || typeof d.component_hours !== 'object') {
    d.component_hours = {};
  }

  // 2) Normalize label exactly like backend does (.strip())
  const key = String(componentLabel || '').trim();
  d.component_hours[key] = Number(newHours) || 0;

  // 3) Update the deliverable Hours to the sum of components
  const sum = Object.values(d.component_hours)
    .map(v => Number(v) || 0)
    .reduce((a, b) => a + b, 0);

  d.Hours = sum;          // keep schema in sync with backend expectations
  d.hours = sum;

  // 4) Mark pricing dirty so Update Pricing + exports will sync
  window.pricingDetailsDirty = true;
  window.pricingDirty = true;
  window.SCENARIO_DIRTY = true;
}


Important checks for the Replit team:

The delegated input / change handler for the component hours inputs must call this function with:

deliverableCode coming from data‑attribute on the row (data-deliverable-code)

componentLabel coming from the left‑hand label (“Visual Elements/Comps”)

Don’t just change the DOM; the scenario object has to be updated.

3.3 Update Pricing button (bottom‑right of Pricing Details)

Goal: When you click Update Pricing:

The entire window.SCENARIO_A (including component_hours) is synced to backend.

Pricing tiles and the Project Scenario panel are rebuilt from backend.

Implementation behaviour:

async function onUpdatePricingClicked() {
  if (!window.SCENARIO_A) return;

  // 1. Collect any remaining DOM state into scenario
  const scen = collectScenarioFromUi(window.SCENARIO_A);

  // IMPORTANT: collectScenarioFromUi must NOT clobber d.component_hours.
  // It should only read component hours from DOM if d.component_hours
  // is missing for that component.

  // 2. Sync to backend
  await syncScenarioToBackend(scen);  // POST /api/scenario/sync

  // 3. Rebuild pricing from authoritative backend scenario
  await rebuildPricingFromBackend(scen);

  window.pricingDetailsDirty = false;
  window.pricingDirty = false;
  window.SCENARIO_DIRTY = false;
}


Things to explicitly verify in code:

syncScenarioToBackend() serializes component_hours as part of each deliverable in scenario.items.

collectScenarioFromUi() does not wipe out component_hours (it should merge, not replace).

3.4 Before every export (XML, XLSX/CSV, PDFs, Gantt)

Goal: Exports always use the latest scenario with component overrides.

The Replit agent said they added ensureScenarioSyncedBeforeExport(). The behaviour must be:

async function ensureScenarioSyncedBeforeExport() {
  // If nothing has changed, you can early‑out, but ONLY if you are sure
  // component edits also clear the dirty flags.
  if (!window.SCENARIO_DIRTY && !window.pricingDetailsDirty) {
    return;
  }

  const scen = collectScenarioFromUi(window.SCENARIO_A);
  await syncScenarioToBackend(scen);
  window.SCENARIO_DIRTY = false;
  window.pricingDetailsDirty = false;
}


Then, every export button must do:

await ensureScenarioSyncedBeforeExport();
downloadWorkfrontXml();        // or weekly PDF, monthly PDF, XLSX, etc.


If any export path bypasses this, it will use stale 32‑hour values.
