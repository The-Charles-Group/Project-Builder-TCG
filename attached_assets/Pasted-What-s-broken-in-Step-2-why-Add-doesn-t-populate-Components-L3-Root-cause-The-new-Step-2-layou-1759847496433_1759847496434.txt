What’s broken in Step 2 (why “Add” doesn’t populate Components/L3)

Root cause

The new Step‑2 layout renders AI Suggested Deliverables separately from the left “Deliverables” list. Clicking Add updates an internal “chosen” list but doesn’t mark a deliverable as the active selection in the left column.

Because the Components panel populates only when a deliverable is active, it stays in the state “Select a deliverable first…” and never calls the backend /api/components_for endpoint to fill the panel. (That endpoint exists and is healthy.)

Fix (frontend, Step‑2 JS)

Unify selection so there is a single source of truth, and wire the Add buttons to the same handler the left‑hand checkboxes use:

// step2.js (or the file that owns Step 2 UI state)

const S2 = {
  activeDeliverable: null,
  selectedDeliverables: new Set(),                 // codes
  selectedComponentsMap: new Map(),                // code -> Set(component)
  selectedL3Map: new Map(),                        // `${code}|${component}` -> Set(l3)
  cache: { components: new Map(), l3: new Map() }, // reuse data across clicks
  // ... other state
};

// Centralized selector
function selectDeliverable(code) {
  S2.selectedDeliverables.add(code);
  S2.activeDeliverable = code;
  markLeftListChecked(code, true);                 // tick the checkbox in the left column
  renderYourSelectionPill(code);                   // bubble/pill under “Your Selection”

  // Populate components panel
  loadComponentsFor(code);
  // Clear L3 until a component is chosen
  renderL3Panel([]);
  renderSelectionSummary();
}

// Wire AI “Add” buttons to the same selector
document.addEventListener('click', (e) => {
  const btn = e.target.closest('[data-add-deliverable]');
  if (!btn) return;
  const code = btn.getAttribute('data-add-deliverable');
  selectDeliverable(code);
});

// Left column clicks also call selectDeliverable(code)
document.querySelector('#deliverablesList').addEventListener('change', (e) => {
  if (!e.target.matches('input[type="checkbox"][data-code]')) return;
  const code = e.target.getAttribute('data-code');
  if (e.target.checked) selectDeliverable(code);
  else unselectDeliverable(code);
});

function loadComponentsFor(code) {
  // use current Step-3 complexity/tier choices (or defaults) from global app state
  const { complexity, tier } = window.APP_SPEC; // wherever you store it
  fetch(`/api/components_for?deliverable_code=${encodeURIComponent(code)}&complexity=${encodeURIComponent(complexity)}&tier=${encodeURIComponent(tier)}`)
    .then(r=>r.json())
    .then(data => {
      S2.cache.components.set(code, data.components || []);
      renderComponentsPanel(code, data.components || []);
    })
    .catch(console.error);
}


Why this works: Components now refresh as soon as Add is pressed, because it uses the exact same flow as selecting the deliverable in the left column.

Add a tiny backend to support “L3 Subtasks” (if not already wired)

Your server already supports component selection and carries that mapping all the way into Scenario A/B pricing and exports (the code expects selected_components_map and also inflates if empty) . What’s missing in 2.8.1 is a thin read API to fetch the L3 list for a given Component so the new panel can populate.

Add this endpoint to main.py (FastAPI):

# --- L3 Subtasks browser for a specific Component ---
@app.get("/api/l3_for")
def api_l3_for(deliverable_code: str, component: str, scenario_letter: str="A"):
    if not DB.loaded:
        DB.load()

    dcode = str(deliverable_code)
    comp = str(component)

    # Decide which hours column to read from (same resolver used elsewhere)
    scen_col = DB.scenario_hours_column(scenario_letter) if hasattr(DB, "scenario_hours_column") else "Hours_v4"

    # Pull rows for this deliverable+component from the canonical table
    sub = DB.all_rows[
        (DB.all_rows["Deliverable_Code"].astype(str) == dcode) &
        (DB.all_rows["Component"].astype(str) == comp)
    ].copy()

    if sub.empty:
        return {"l3": []}

    # Normalize a task label column name (many DBs already expose 'task_label')
    label_col = "task_label" if "task_label" in sub.columns else ("Task_Label" if "Task_Label" in sub.columns else "Task")
    sub[label_col] = sub[label_col].astype(str)

    # Hours per L3 (sum across task groups)
    if scen_col in sub.columns:
        g = sub.groupby(label_col)[scen_col].sum()
        rows = [{"name": k, "hours": float(v)} for k, v in g.to_dict().items()]
    else:
        rows = [{"name": x, "hours": 0.0} for x in sorted(sub[label_col].unique())]

    # Also return which task_groups each L3 sits under (helpful for later)
    if "task_group" in sub.columns:
        tg_map = sub.groupby(label_col)["task_group"].apply(lambda s: sorted(set(map(str, s)))).to_dict()
        for r in rows:
            r["task_groups"] = tg_map.get(r["name"], [])

    return {"l3": rows}


That mirrors how hours and labels are already computed elsewhere in the backend and doesn’t change any pricing behavior.

Hook up in the frontend:

function loadL3ForActive(deliverableCode, componentName) {

    .then(data => {
      S2.cache.l3.set(`${deliverableCode}|${componentName}`, data.l3 || []);

    });
}
