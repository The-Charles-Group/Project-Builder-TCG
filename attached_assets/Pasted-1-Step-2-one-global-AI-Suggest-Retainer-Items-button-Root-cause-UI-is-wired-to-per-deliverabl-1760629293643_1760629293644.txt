1) Step 2 — one global “AI Suggest Retainer Items” button

Root cause: UI is wired to per‑deliverable “Retainer” toggles. The backend already exposes a batch retainer suggestion endpoint—use it once for all selected deliverables.

What to call

POST /api/pricing/retainer_suggest
Payload: { "deliverable_codes": ["deck_strategy","guidelines",...], "rfp_text": "<RFP text>" }
Returns { "suggestions": [{deliverable_code, deliverable_name, suggested_months, reasoning}, ...] }.

Frontend change

Add a single button: “🤖 AI Suggest Retainer Items”.

On click:

Gather the selected deliverable codes from the left column.

POST to /api/pricing/retainer_suggest with the RFP text you already store from Step 1.

For each suggestion, set item.retainer_months = suggested_months in your in‑memory scenario store.

Optional: If you want PROJECT vs RETAINER classification (not months) you can also (or instead) call POST /api/ai/analyze_project_retainer with { rfp_text, deliverables:[{code,name}] } and then set retainer flags based on its output.

2) Step 2 — L2 tasks don’t appear after Apply Smart Selection

Root cause (2 parts):

The AI suggest API returns tasks under the key l3_by_component (legacy label) which the UI expects as L2. If the UI only copies deliverables + components and ignores this map during “Apply Selected…”, the right column stays empty until you click components manually.

A state race forces a second click—your handler likely commits selected components first and defers populating tasks until a component is made “active”.

Fix

When the user clicks Apply Selected to Manual Selection:

Merge deliverables and components and flatten l3_by_component[component] into the selected L2 list immediately.

Normalize the label: l2Tasks = payload.l3_by_component (simple rename).

After commit, auto‑set the first selected component as active so the right column renders immediately.

Pseudocode

// After Smart Selection
const { components, l3_by_component } = aiPayload;
state.selectedComponents = dedupe(components.map(c => c.name));
state.selectedL2 = flatten(Object.entries(l3_by_component)
  .map(([comp, tasks]) => tasks.map(t => ({ component: comp, ...t })))); // map to your L2 shape
state.activeComponent = state.selectedComponents[0] || null; // show tasks without extra click

3) Step 3 — Grand Total = $0, and 3 buttons do nothing
3a) Grand total shows $0

Root cause: The UI isn’t reading scenario totals. The backend returns scenarios with totals.hours and totals.price; use those.

Fix:
Compute:
grandTotal = scenarios.A.totals.price + (retainerMonthlyCost * 12)
and show scenarios.A.totals.price even if retainer is $0.

3b) Buttons wiring

Build/Re‑build Scenario: The Brad build exposes /api/scenarios (POST/GET) as the canonical builder/recovery endpoints. Make sure your button hits this route with the selected codes, pricing mode, blended rate, rate band, project start, and retainer months map.

AI Suggest Type: Wire to POST /api/ai/analyze_project_retainer (see #1). Use the returned type (PROJECT/RETAINER) per deliverable to set retainer_months (e.g., default 12 for RETAINER) and refresh the scenario.

Optimize All Pricing: Use POST /api/pricing/redistribute-hours to redistribute hours across components for a deliverable when you change its total hours; loop this across selected deliverables when the user clicks “Optimize”.

Export Pricing Details (xlsx/csv): Call POST /api/export with the current scenario object plus file_format: "xlsx" (or csv). Backend inflates missing pieces and returns a download. This does not depend on Step 4.

4) Step 4 — Timeline “Request Timeout”

What exists: POST /api/ai/generate_timeline with SSE progress streaming (see docstring). The app mounts an SSE router—use streaming on the client and increase fetch timeout.

Frontend changes

Use EventSource (or fetch + ReadableStream) to consume SSE so the request doesn’t trip your default 30s timeout.

Show server progress; on completion, parse the timeline payload and render the Gantt.

Server guardrails on Replit

Start uvicorn with a larger timeout (e.g., --timeout-keep-alive 120).

If you still hit resource limits, generate the timeline for Scenario A only and/or cap concurrent deliverables while you test.

5) Step 5 — Exports

Excel/CSV: Use /api/export from Step 3 data (works without the timeline).

MS Project XML: Use the XML export route that builds a temp Excel, then runs convert_excel_to_mspdi(...) and streams a file response. Ensure you pass project_start, sheet_name, and the scenario you edited. Any hours/rates you edited in the UI will flow into the XML because the export builds the WBS from the scenario you send.

If you previously saw a 500 on XML: it usually means either the temp Excel wasn’t written or the payload missed required fields (pricing_mode, rate_band, or project_start). The XML exporter expects those and cleans up temp files after.

6) Ensuring edited hours & pricing show up in exports

Both /api/export and the XML exporter first call build_wbs_dataframe_from_scenario(scenario, project_name); that function reads whatever you have in memory. So: always mutate the scenario object (items → components → tasks with new hours, rate, price) before calling export. Then the outputs will match the UI.
