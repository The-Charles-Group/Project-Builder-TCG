0) What’s actually breaking Step 3

Root cause: the Step‑2 UI now selects L2 task groups, but the server’s Step‑3 builder still only reads selected_l3_map. When this map is missing, the builder inflates every component → includes all task groups for each deliverable, producing a very large WBS and big JSON payload back to the browser (causing the freeze). See the Step‑3 /api/scenarios handler; it only extracts selected_l3_map / selectedL3Map / l3Map and never looks for the new L2 payload names.

The WBS builder itself will happily expand to all task groups when the map is empty via _inflate_components_if_missing, which we do call in the build pipeline. That safeguard is good for exports, but it’s harmful here because the UI expects a filtered set.

Change B — don’t silently inflate to ALL task groups when a filtered map was sent

In the downstream inflation helper you already use (_inflate_components_if_missing), inflation is triggered when the map is empty or equals "__ALL__". Keep that logic, but only run it when no task group map was provided at all (i.e., task_group_map is None). If the UI sent a map—even if it’s empty for a given component—respect it.

Where: the inflation is shown in the build path and WBS path. The current code populates “included_task_groups” whenever the map is missing/empty/"__ALL__".

Minimal guard example (add at the start of _inflate_components_if_missing or where you set included_task_groups[_map]):

# If the scenario was built with an explicit task_group_map from the UI,
# skip inflation; only inflate if no map was provided for this deliverable at all.
explicit_map_present = bool(item.get("included_task_groups_map", None) not in (None, "__ALL__"))
if explicit_map_present:
    continue


This keeps exports safe while preventing Step 3 from ballooning.

2) Keep the response light for the pricing table

The pricing table only needs deliverable/component totals and rollups to compute the “One‑time” and “Monthly Retainer” boxes and Grand Total. The builder already returns scenario totals; the code path that responds from /api/scenarios includes totals in result.get("totals", {}). Make sure the FE uses scenarios.A.totals.price and scenarios.A.totals.hours (and adds 12 × monthly_retainer_cost) for the Grand Total instead of recalculating from the whole WBS.
