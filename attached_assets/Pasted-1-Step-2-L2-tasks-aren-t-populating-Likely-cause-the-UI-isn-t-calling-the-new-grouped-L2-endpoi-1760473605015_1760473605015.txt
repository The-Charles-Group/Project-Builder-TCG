1) Step 2 — L2 tasks aren’t populating

Likely cause: the UI isn’t calling the new grouped L2 endpoint after “Apply Smart Selection,” or it’s still keyed to the old “L3” merge.
Fix:

Call POST /api/step2/l3/bulk with { deliverable, components[] } and render the returned object { [component]: [task_labels] } in the “L2 Tasks” widget. The endpoint already normalizes Task_Label and falls back to task_group when labels are missing. It also handles the “General” component by treating it as empty/missing component rows.

If your right‑panel label says L3, change the UI copy to L2 only; the data contract is already L2‑friendly.

Why the counter shows “219 L2 tasks” but the panel is empty: the AI suggestion call /api/step2/ai/suggest returns l3_by_component counts, but unless you follow with /api/step2/l3/bulk the widget won’t have items to render.

Request example

POST /api/step2/l3/bulk
{ "deliverable": "deck_strategy", "components": ["brief","art_direction","general"] }


(Returns component → tasks map ready for the widget.)

2) “Retainer optionality” needs to appear

Two supporting pieces are already in the API:

Project vs Retainer analysis (per deliverable) — POST /api/pricing/analyze-retainer returns a recommendation + reasoning for each deliverable; use it to pre‑toggle the Retainer switch and set suggested months.

Retainer suggestion (batch) — POST /api/pricing/retainer_suggest for quick hints across many deliverables.

When you rebuild (Step 3), retainer months are carried on each item; exports include a retainer summary dataframe. (See retainer rows builder.)

3) Step 3 — Pricing table must be editable

Backend already accepts per‑component overrides via selected_components_map when you (re)build the scenario. Each entry can be { "component": hours } (hours None = default; <=0 = unselect). Send the edited values back into POST /api/build and re‑render the table from the returned scenario.

4) Optimize Pricing button (hour redistribution)

Use the new endpoint POST /api/pricing/redistribute-hours. Important: payload expects components: [{ "name": ..., "hours": ...}] (not current_hours). It returns suggested hours, deltas, and reasoning per component. Wire the response back into your grid.
Example (minimal):

{
  "deliverable_name":"Brand Strategy",
  "deliverable_code":"deck_strategy",
  "new_total_hours":150,
  "components":[{"name":"Market Research","hours":40},{"name":"Strategy Development","hours":50}],
  "complexity":"Advanced","tier":"T2_MediumVolume","use_ai":true
}


5) AI Suggest Type (Project vs Retainer)

Hook the button to POST /api/pricing/analyze-retainer for a single deliverable, or to the broader analyzer that classifies all selected deliverables with confidence + reasoning. Use the returned type and reasoning to pre‑set the Step‑3 retainer toggle and months.

6) Rebuild Scenario

Two supported flows:

Versioned “Rebuild”: clone current scenario via POST /api/scenario/duplicate (gives v2/v3…) and let the user edit that version.

Hard rebuild: call POST /api/build again with the edited selected_components_map, pricing mode/rate band, and retainer months to regenerate A (and B, if you use it).

7) Export Pricing Details

If you want a Workfront‑ready CSV/XLSX from the current scenario, call POST /api/export (CSV or XLSX). This is the right hook for a “Export pricing details” button in Step 3.
If the user ran the timeline optimizer, the schedule module also exposes downloads (XML/Gantt/Explanations/Audit) via GET /api/schedule/download/{file_type}/{base_name}.
For final “ship everything” exports (Excel + XMLs + ZIP), use Final Ship and GET /api/project/download/{ship_id}.

8) AI Reasoning (Step 4)

The timeline generator streams progress and explicitly enters an ai_reasoning stage; the result includes reasoning you can surface behind the button. Use POST /api/ai/generate_timeline (SSE progress) and display result.reasoning. If the user optimized a schedule, you can also fetch explanations JSON via the schedule download endpoint and show that.

9) (Nice‑to‑have) Clear stale state

Brad’s build includes a POST /api/clear_session to wipe cached RFP text/embeddings if you see the “holding onto past SOW references” behavior. Trigger it on “Start New Project.”
