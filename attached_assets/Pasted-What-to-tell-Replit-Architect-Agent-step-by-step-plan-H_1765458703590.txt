Task 1 – Treat backend scenario as the single source of truth

Goal: whenever Step 3 opens, both panels (Project Scenario + Deliverable Pricing Details) are populated from the same canonical scenario coming from the backend.

In the Step 3 JS, create an initPricingStep() that runs on DOMContentLoaded (or when Step 3 is shown).

initPricingStep() should:

async function initPricingStep() {
  const sessionId = window.SESSION_ID; // however you’re storing it

  // 1) Ask backend for current working scenario without rebuilding
  const res = await fetch('/api/scenarios', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ session_id: sessionId, reset: false })
  });

  const data = await res.json();  // { A: scenarioA, ... }

  window.SCENARIO_A = data.A;

  // 2) Use the existing helper to rebuild pricing from backend
  await rebuildPricingFromBackend(window.SCENARIO_A);

  // IMPORTANT: rebuildPricingFromBackend must update BOTH:
  // - Project Scenario table
  // - Deliverable Pricing Details table
}


Ensure buildScenariosAB() is only used during the Step‑2 → Step‑3 transition to seed the scenario once. After that, all loads should go through /api/scenarios + rebuildPricingFromBackend().

function onPricingDetailsChange(e) {
  const input = e.target;
  if (!input.matches('input, select')) return;

  const dcode = input.dataset.deliverableCode;
  const component = input.dataset.componentName || null;
  const field = input.dataset.field;
  const value = input.type === 'number' ? parseFloat(input.value || '0') : input.value;

  applyPricingEditToScenario(dcode, component, field, value);
  window.pricingDetailsDirty = true;
}


Implement applyPricingEditToScenario like this:

function findScenarioItemByCode(dcode) {
  return (window.SCENARIO_A.items || []).find(
    it => String(it.deliverable_code || it.code) === String(dcode)
  );
}

function applyPricingEditToScenario(dcode, component, field, value) {
  const item = findScenarioItemByCode(dcode);
  if (!item) return;

  // 1) Ensure we have a component_hours map per deliverable
  item.component_hours = item.component_hours || {};

  if (component) {
    // editing a component row
    if (field === 'hours') {
      item.component_hours[component] = value;
    }
    // (later you can optionally support component-level rate overrides)
  } else {
    // editing the deliverable header row
    if (field === 'hours') {
      // keep backend happy: populate all accepted hour fields
      item.Planned_Hours = value;
      item.planned_hours = value;
      item.hours = value;
    }
    if (field === 'rate') {
      item.rate = value;
    }
  }

  // 2) When a component hours changes, re-sum and update header hours too
  if (component && field === 'hours') {
    const sum = Object.values(item.component_hours)
      .map(v => Number(v) || 0)
      .reduce((a, b) => a + b, 0);

    item.Planned_Hours = sum;
    item.planned_hours = sum;
    item.hours = sum;

    // Also update the header Hours input in the UI so user sees it
    const headerInput = document.querySelector(
      `input[data-deliverable-code="${dcode}"][data-component-name=""][data-field="hours"]`
    );
    if (headerInput) headerInput.value = sum.toString();
  }
}


This makes the deliverable total hours = sum of component hours and stores component overrides in item.component_hours.

Task 3 – Make Update Pricing actually sync those edits

Goal: clicking “Update Pricing” should:

Sync the edited scenario (now including component_hours and new Planned_Hours) to the backend.

Ask the backend to recompute authoritative pricing.

Refresh both panels from backend data.

Ensure exports will see the same numbers because they use the same scenario.

Implementation:

async function onUpdatePricingClicked() {
  if (!window.pricingDetailsDirty) {
    // nothing to do
    return;
  }

  const sessionId = window.SESSION_ID;

  // 1) Sync scenario edits to backend
  await fetch('/api/scenario/sync', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      session_id: sessionId,
      letter: 'A',
      scenario: window.SCENARIO_A
    })
  });

  // 2) Ask backend to rebuild pricing + breakdown from the synced scenario
  await rebuildPricingFromBackend(window.SCENARIO_A);

  // 3) Clear dirty flag
  window.pricingDetailsDirty = false;
}


Hook this handler to the “Update Pricing” button in the Pricing Details panel.

Just before you call the export endpoint on the client, it’s safest to run one more sync:

async function exportWorkfront() {
  const sessionId = window.SESSION_ID;

  // Last-chance sync of any unsaved edits
  await fetch('/api/scenario/sync', { ...window.SCENARIO_A payload... });

  // Now call the actual export endpoint
  window.location.href = `/api/export_workfront?session_id=${encodeURIComponent(sessionId)}&letter=A`;
}


That way even if someone forgets to click “Update Pricing”, the export still sees the latest grid values.
