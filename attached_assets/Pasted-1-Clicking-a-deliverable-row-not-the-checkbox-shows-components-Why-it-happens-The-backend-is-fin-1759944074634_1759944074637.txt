1) Clicking a deliverable row (not the checkbox) shows components

Why it happens
The backend is fine; it simply returns components for a deliverable code. The issue is UI-level: the row click is treated like a “selection” instead of a “preview”, so the Components column refreshes even when the deliverable hasn’t been added to “Selected”. (You can see the server endpoint is just a simple component lookup and doesn’t persist any selection state. 

v2.8.1 prod

)

Fix (UI)
Separate preview from select:

Row <li onClick> ⇒ only set a previewDeliverableCode (do not mutate selectedDeliverables or summary counts).

Checkbox onChange ⇒ toggle the real selection and then fetch components for the newly selected codes.

Add e.stopPropagation() on the checkbox so row clicks don’t fire it accidentally.

Patch sketch (React/TS)

// before: row click toggled selection and fetched components
<li onClick={() => toggleSelect(d.code)}>
  <input
    type="checkbox"
    checked={selected.has(d.code)}
    onChange={() => toggleSelect(d.code)}
  />
  {d.label}
</li>

// after: row click = preview only; checkbox = selection source of truth
<li onClick={() => setPreviewDeliverable(d.code)}>
  <input
    type="checkbox"
    checked={selected.has(d.code)}
    onChange={(e) => { e.stopPropagation(); toggleSelect(d.code); }}
  />
  {d.label}
</li>


With this, “Components” only populates when the box is checked, and your Summary panel stays consistent.

2) Exported XML still contains “Start — … / End — …” rows (and even End — nan)

Why it happens
During MSPDI conversion we always enrich the WBS by inserting synthetic START/END anchors per deliverable. Those are the ANCHOR_90xxx rows and are labeled "Start — {dname}" and "End — {dname}". This is done in enrich_wbs_for_workfront(...), which the converter calls unconditionally.

Two-part fix (backend)

Make anchors optional (default OFF). Add a boolean flag to the converter and only call the enrichment when true.

Never display “nan” in anchor labels. The enrichment currently builds dname from a possibly empty deliverable label or a raw code; if the code is NaN/empty, you get “nan”. Use the already computed safe_code(...) fallback for the label.

3) After removing an L3 subtask you can’t add it back (unless you re-add via AI suggestions)

Why it happens
L3 removal is tracked only in the UI state; when you unselect/reselect a component, the UI keeps a “hidden L3” set and does not repopulate from the backend. The backend L3 endpoints always return the full set (falling back to task_group if Task_Label is missing), so the source-of-truth is there and correct. 

v2.8.1 prod

Fix (UI)

When a component is toggled back on, clear the hidden L3 set for that (deliverable, component) and refetch with /api/step2/l3 or /api/step2/l3/bulk.

Provide an explicit “Reset subtasks” (per component) that discards the local removals and rehydrates from the server.

If you cache L3 in a Map<deliverable, Map<component, string[]>>, introduce a parallel Map<deliverable, Map<component, Set<string>>> for hidden; clearing the component selection should delete its hidden entry.

The server L3 APIs already support merged and per-component lists you can use to repopulate.

4) Components appear but no L3 list, while the Summary shows “53 subtasks”

Why it happens
The Summary’s “L3 Subtasks” counter is being computed from stale or cached L3 for previous selections, not from the L3 arrays actually rendered for the currently selected (deliverable, components). This is consistent with the screenshot where the Components count is 0 but L3 shows 53.

Fix (UI)

Recompute the L3 count only from the same data structure that drives the L3 UI list (i.e., visible L3 = server L3 minus hiddenL3 for each selected (deliverable, component)).

On deliverable selection changes, invalidate any L3 caches for deselected deliverables.

Add a guard: if selectedComponents.size === 0 for a deliverable, its contribution to L3 Subtasks must be 0.

Precise code references you can verify

Anchors are created here (Start — ... / End — ... with ANCHOR_... WBS) and are currently unconditional: add the flag and the “nan” guard as shown above.
