Goal: Make Workfront see correct planned hours by fixing Units, keeping fixed‑duration semantics, and keeping durations realistic.

1) Stop Units from being scaled to 100

A. Output Units as a decimal with 4 places
In the XML writer (the block that emits <Assignments>), change:

# BEFORE
SubElement(assignment, "Units").text = str(units)


to:

# AFTER (MSPDI expects 1.0 = 100%)
SubElement(assignment, "Units").text = f"{units:.4f}"


(That code path is in the section that computes work_min / dur_min and writes Units; see the current writer logic. )

B. Temporarily disable the post‑processor that is likely rewriting Units
Anywhere we call post_process_xml(...), disable it until it’s audited:

# BEFORE
if PARALLELIZE_IDENTICAL_NAMES:
    final_xml = post_process_xml(output_xml)

# AFTER
PARALLELIZE_IDENTICAL_NAMES = False  # add this near config/constants
# ...and remove/skip the post_process_xml call for now
final_xml = output_xml


This call exists in multiple export endpoints; set the flag false (or comment out the call) in all of them (single XML, workbook XML, ABC exports, etc.).

Rationale: The core writer computes Units correctly as a ratio. Your file shows <Units>100</Units>, so something after the writer is converting it. Disabling post‑processing isolates the problem immediately.

2) Keep Fixed‑Duration tasks, but don’t over‑round duration

You’re already emitting Fixed Duration for leaves (<Type>1</Type>) which is correct.
What inflates hours is the forced rounding to whole days. So only round up to a day when the span actually crosses working‑day boundaries. Replace:

# BEFORE (always snaps)
dur_minutes = ((dur_minutes + 479) // 480) * 480


with:

# AFTER (only if within-day rounding would cause <8h to become a full day)
if dur_minutes >= 480:
    dur_minutes = ((dur_minutes + 479) // 480) * 480
# else leave shorter tasks as-is to preserve small planned work


This avoids turning a 2h task into 8h unless it truly spans a full business day. (Original snap is here. )
