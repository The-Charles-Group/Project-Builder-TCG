What to change in your generator (Replit)

Below is a precise checklist you can hand to your Replit agent. It removes the phases/approvals/“- COMPLETE” rows, stops duplicates, fixes outline numbers, and keeps hours/dependencies/revenue consistent.

0) Pre‑export validation (fail fast)

Before writing the XML string, run these checks on the in‑memory task list:

UID uniqueness: assert all_unique(task.uid)

WBS/OutlineNumber parity: For every task, task.OutlineNumber == task.WBS (or generate OutlineNumber from the parent’s OutlineNumber + child index). Reject any value that ends with . or has double dots.

Parent/child outline sanity: OutlineLevel == OutlineNumber.split('.').length.

Predecessors: every PredecessorUID must exist in the task UID set; drop links pointing to missing UIDs.

Assignments cross‑reference: If you emit <Assignments>, every Assignment.TaskUID and Assignment.ResourceUID must exist in <Tasks>/<Resources> respectively.

1) Remove phases, client approvals, and “- COMPLETE” rows

In the transformation from your internal plan → MSP tasks, filter out any task whose name matches:

(?i)\bphase\s*\d+\b

(?i)\bclient\s*approval\b

(?i)\s-\s*complete$

This stops summary rows that artificially push finish dates and clutter Workfront.

2) De‑duplicate tasks inside components

Within each component (i.e., same parent WBS), keep only one task per (NormalizedName, Role/Dept, Start, Finish) key. “NormalizedName” should lowercase, strip punctuation, and collapse whitespace so “Activation Ideas” and “Activation Ideas” are the same. If duplicates collide, pick the one with assignments or the earliest Start.

3) Generate clean WBS / OutlineNumber / OutlineLevel

Compute WBS purely from the tree:

Deliverable D → 1, 2, 3, …

Component C under D → D.i

Task T under C → D.i.j

Set OutlineNumber = WBS, and OutlineLevel = WBS.count('.') + 1.

Never write a value ending with a dot. (This directly fixes the 9. issue in the failing file.)

4) Dates, duration, work (hours), and predecessors

Use your calendar of 480 minutes/day and business days only when converting.

Task Duration must be ISO 8601 minutes (e.g., 1 day = PT1440M); compute from working time between Start and Finish.

Work (planned hours) on the task should equal the sum of assignment Work in minutes; e.g., 6 hours → PT360M.

Predecessors: write <PredecessorLink> with existing PredecessorUIDs only; for Finish‑to‑Start, Type=1 with LinkLag=0 is fine.

5) Resources & assignments

If you include <Assignments>, every ResourceUID must exist in <Resources>.

Set Assignment.Units as a fraction (1.0 = 100%).

If you don’t want to allocate people yet, you can safely leave <Assignments /> empty (this is importable as shown in your earlier file).

6) Planned revenue

Keep revenue in ExtendedAttributes → Number3 (FieldID 188743715), alias Revenue. That’s how your accepted file is already structured.
