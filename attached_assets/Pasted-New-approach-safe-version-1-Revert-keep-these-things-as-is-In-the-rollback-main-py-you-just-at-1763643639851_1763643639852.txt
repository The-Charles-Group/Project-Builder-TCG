3. New, simple PredecessorLink builder (WBS-based)

After you’ve finalized rows (post-any grouping you do) and have uid_to_sched:

# Build WBS -> UID map from the FINAL rows list
wbs_to_uid = {r["WBS"]: r["UID"] for r in rows if r.get("WBS")}

predecessors_elem = SubElement(project, "PredecessorLinks")

for r in rows:
    wbs = r.get("WBS")
    deps_str = (r.get("Dependencies") or "").strip()
    if not deps_str:
        continue

    # OPTIONAL: only attach dependencies for high-level tasks
    outline = int(r.get("OutlineLevel", 0) or 0)
    if outline > 5:
        continue  # no leaf-to-leaf conga line, ever

    succ_uid = r["UID"]
    for dep_wbs in deps_str.split(","):
        dep_wbs = dep_wbs.strip()
        if not dep_wbs:
            continue

        pred_uid = wbs_to_uid.get(dep_wbs)
        if not pred_uid or pred_uid == succ_uid:
            continue

        link = SubElement(predecessors_elem, "PredecessorLink")
        SubElement(link, "PredecessorUID").text = str(pred_uid)
        SubElement(link, "SuccessorUID").text = str(succ_uid)
        SubElement(link, "Type").text = "1"   # Finish-to-Start
        SubElement(link, "CrossProject").text = "0"
        SubElement(link, "LinkLag").text = "0"
        SubElement(link, "LagFormat").text = "7"


Key properties of this approach:

Dependencies are only between WBS parents (L1–L5), never between roles.

No uid_alias_map needed.

Multi-assignment or L5-only transformations can happen freely, as long as:

rows contain the WBS you care about

wbs_to_uid points to the right row for that WBS.

This enforces exactly the “L5 to L5 component chain” Ross wants, without ever touching role-level predecessors.
