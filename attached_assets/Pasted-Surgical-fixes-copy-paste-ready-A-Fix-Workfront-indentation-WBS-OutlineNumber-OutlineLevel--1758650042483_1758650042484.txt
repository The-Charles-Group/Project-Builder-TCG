C) Persist Step‑4 resequencing so dates move

Replace your v2.6 /api/reorder_timeline with the persisting version from v2.5 (or add the same persistence lines). The key is to update the scenario in memory and return the full scenario so the UI state and exporter stay in sync. Minimal diff:

@app.post("/api/resequence_timeline")
def api_resequence_timeline(p: ResequencePayload):
    letter = (p.scenario_letter or "A").upper()
    scen = _current_scenarios().get(letter)
    if not scen:
        raise HTTPException(400, f"Scenario {letter} not built")

    items = list(scen.get("items") or [])
    by_code = {str(it.get("deliverable_code") or it.get("code")): it for it in items}
    want = [str(c) for c in p.ordered_deliverable_codes]

    ordered = [by_code[c] for c in want]
    scen["items"] = ordered
    scen["timeline"] = {
        "start": ordered[0]["schedule"][0]["start_date"],
        "end":   ordered[-1]["schedule"][-1]["end_date"],
    }
    _CURRENT_SCENARIOS[letter] = scen  # <-- persist

    return {"items":[{"deliverable_code": d["deliverable_code"], "schedule": d["schedule"]} for d in ordered],
            "scenario": scen}


This is the exact persistence logic v2.5 uses and is why re‑ordering there repaints dates and exports correctly.

Also keep your “rebuild sequential schedule” route (/api/reorder_timeline) if you like, but after computing its items, write them back into _CURRENT_SCENARIOS[letter] the same way. Your current v2.6 version returns items but doesn’t persist them.
