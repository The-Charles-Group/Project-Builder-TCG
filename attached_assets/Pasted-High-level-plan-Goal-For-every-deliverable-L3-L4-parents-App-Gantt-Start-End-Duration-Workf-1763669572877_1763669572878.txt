High-level plan

Goal: For every deliverable (L3, L4 parents):

App Gantt Start/End/Duration ≈ Workfront Start/End/Duration immediately after import
(CPD example: whatever WF calculates for 1.1.1, your app should show the same.)

Strategy:

Schedule the WBS tasks yourself in the exporter using the same rules Workfront uses (FS deps, business days, 8h/day).

Roll up those dates to the parents (L3/L4/etc).

Use those rolled-up dates everywhere:

For the app Gantt bars & tooltips.

For the <Start> / <Finish> in the XML (instead of the old “115-day” deliverable dates).

Workfront will then just be re-reading the schedule you already calculated, so it won’t surprise you with different dates.

Concrete steps for Replit agent / architect
1. Choose the source of truth

Decide this explicitly in the code comments:

The WBS rows (L4/L5/L6 + WBS-based dependencies) are the scheduling source of truth.
Deliverable (L3/L2/L1) dates are derived, never independently calculated.

That means:

Stop using the old build_schedule / scenario-level timeline to drive L3 durations in the Gantt.

Instead, compute dates from the WBS graph.

2. Add a WBS scheduler

Create a helper in the exporter (or a shared scheduling module):

def compute_wbs_schedule(rows, normalized_edges, project_start_date):
    """
    rows: list of dicts, each with at least:
        - 'UID'
        - 'WBS'
        - 'Hours' (planned hours)
    normalized_edges: list of (pred_wbs, succ_wbs) from WBS dependency builder
    project_start_date: datetime.date
    
    Returns:
        uid_to_sched: {uid: {"start": date, "finish": date, "duration_days": float}}
    """


Inside:

Build a graph in UID space:

wbs_to_uid = {r["WBS"]: r["UID"] for r in rows}
preds = {uid: [] for uid in wbs_to_uid.values()}
for pred_wbs, succ_wbs in normalized_edges:
    pred_uid = wbs_to_uid[pred_wbs]
    succ_uid = wbs_to_uid[succ_wbs]
    preds[succ_uid].append(pred_uid)


Convert Hours → DurationDays per task:

Use Workfront’s convention: 8h = 1 day.

For each row: duration_days = row["Hours"] / 8.0
(you can add utilization logic later if needed, but start simple – this is what WF does internally.)

Topologically sort the tasks by dependencies.

For each task in topo order:

# earliest start in business days (offset from project_start)
if preds[uid]:
    est_days = max(eft_days[p] for p in preds[uid])  # FS only
else:
    est_days = 0

dur_days = duration_days[uid]
eft_days[uid] = est_days + dur_days


Convert the day offsets into actual dates with your existing US+MX business calendar (same one you already use in AgencyDB):

start_date = add_business_days(project_start_date, est_days)
finish_date = add_business_days(start_date, dur_days)


Store:

uid_to_sched[uid] = {
    "start": start_date,
    "finish": finish_date,
    "duration_days": dur_days,
}


This gives you a “Workfront-like” schedule for every WBS row before you generate XML or Gantt JSON.

3. Roll up to parents (L3/L4/etc)

Now roll up those dates to all summary rows:

# First, attach schedule to rows by UID
uid_to_row = {r["UID"]: r for r in rows}
for uid, sched in uid_to_sched.items():
    r = uid_to_row[uid]
    r["StartDate"] = sched["start"]
    r["FinishDate"] = sched["finish"]
    r["DurationDays"] = sched["duration_days"]

# Then, roll up parent tasks (do this from deepest to shallowest)
rows_sorted_by_outline = sorted(rows, key=lambda r: r["WBS"].count("."), reverse=True)

for r in rows_sorted_by_outline:
    wbs = r["WBS"]
    outline = wbs.count(".") + 1
    if outline <= 3:  # L3 and above are parents in your model
        # Find all descendants
        children = [c for c in rows 
                    if c["WBS"].startswith(wbs + ".")]

        if not children:
            continue

        r["StartDate"]  = min(c["StartDate"]  for c in children)
        r["FinishDate"] = max(c["FinishDate"] for c in children)
        # business-day diff between start and finish
        r["DurationDays"] = business_day_diff(r["StartDate"], r["FinishDate"])


For Creative Strategy / Campaign Plan Deck (WBS 1.1.1), this will give you:

StartDate = earliest L4/L5 child start

FinishDate = latest L4/L5 child finish

DurationDays = working days between them

→ which should be very close to the 71 days / 5/26–9/3 that Workfront shows.

4. Wire this into XML export

In the XML writer, instead of using the old deliverable dates:

SubElement(task_elem, "Start").text  = row["Start"]  # OLD
SubElement(task_elem, "Finish").text = row["Finish"] # OLD


switch to the scheduled ones:

start_dt = row["StartDate"]
finish_dt = row["FinishDate"]
SubElement(task_elem, "Start").text  = start_dt.strftime("%Y-%m-%dT08:00:00")
SubElement(task_elem, "Finish").text = finish_dt.strftime("%Y-%m-%dT17:00:00")

# Optionally set Duration based on duration_days * 480 minutes
minutes = int(row["DurationDays"] * 480)
SubElement(task_elem, "Duration").text = f"PT{minutes}M"


Do this for all rows (leaves and parents), but remember Workfront will recompute parents anyway. Because you’re now using the same schedule to drive both, they should line up.

5. Wire this into the app Gantt

Wherever you build the JSON for the frontend Gantt:

Stop using the old scenario.start_date / scenario.end_date / scenario.duration_days for deliverables.

Instead, use the rolled-up values we just attached to the L3 rows:

gantt_item = {
    "name": row["Name"],
    "start": row["StartDate"].isoformat(),
    "end": row["FinishDate"].isoformat(),
    "duration_days": row["DurationDays"],
    "hours": row["Hours"],
    ...
}


That’s what will change your tooltip for CPD from:

2026-05-25 → 2026-09-16 (115 days)

to something like:

2026-05-26 → 2026-09-03 (~71 days)

matching Workfront’s summary.

6. Apply to all deliverables

Because this is based on WBS + dependencies, it automatically scales:

Brand Positioning Strategy, Brand Narrative, etc. all roll up from their own L4/L5 children.

Higher parents (Strategy, Project Summary) roll up from their descendants too.

You don’t need special-case logic per deliverable – the WBS hierarchy drives everything.
