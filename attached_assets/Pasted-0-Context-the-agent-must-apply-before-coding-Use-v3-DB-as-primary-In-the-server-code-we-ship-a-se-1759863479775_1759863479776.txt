async function hydrateComponentsFor(delivCode) {
  const comps = await api(`/api/components?deliverable=${encodeURIComponent(delivCode)}`);
  selectionStore.componentsByDeliv.set(delivCode, new Set(comps));
  // If no current “component” is selected for L3 preview, auto-select the first
  if (comps.length) {
    await hydrateL3For(delivCode, comps[0]);
  }
}

async function hydrateL3For(delivCode, componentName) {
  const l3 = await api(`/api/l3?deliverable=${encodeURIComponent(delivCode)}&component=${encodeURIComponent(componentName)}`);
  selectionStore.l3ByComponent.set(`${delivCode}::${componentName}`, new Set(l3));
}

(C) Back‑end read APIs for Step 2 UI

Add three simple read endpoints so the front‑end can always drive from the database:

@app.get("/api/components")
def list_components(deliverable: str):
    # use unified schema prepared by AgencyDB (v3 primary, v4 overlay)
    df = db.all_rows
    # normalize deliverable code matching
    deliverable = str(deliverable).strip().lower()
    subset = df[df["Deliverable_Code"].astype(str).str.lower() == deliverable]
    comps = (
        subset["Component"]
        .fillna("")
        .astype(str)
        .str.strip()
        .replace({"nan": ""})
        .unique()
        .tolist()
    )
    return sorted([c for c in comps if c])

@app.get("/api/l3")
def list_l3(deliverable: str, component: str):
    df = db.all_rows
    d = str(deliverable).strip().lower()
    c = str(component).strip().lower()
    sub = df[
        (df["Deliverable_Code"].astype(str).str.lower() == d) &
        (df["Component"].astype(str).str.lower() == c)
    ]
    # Prefer a normalized label column; our loader maps v4 column(s) to 'Task_Label'
    # (see _normalize_task_label_column) :contentReference[oaicite:2]{index=2}
    task_col = "Task_Label" if "Task_Label" in sub.columns else "Task"
    items = (
        sub[task_col]
        .fillna("")
        .astype(str)
        .str.strip()
        .replace({"nan": ""})
        .unique()
        .tolist()
    )
    return sorted([x for x in items if x])


^ These rely on the normalization already present in AgencyDB:

“Component” is unified from Component_Task_L1 and cleans literal "nan" strings.

Task_Label is created for display-level L3 names (v4/v4b).

4) Export XML — bad “[nan] START/END” and “[DEL‑0029] START/END” rows
What’s happening

The exporter creates sentinel tasks: [DeliverableCode] START / END to anchor dependencies between components and L3. That’s fine. But when the deliverable code is missing, the code writes [nan] START/END, and where the code is present but not human‑friendly it writes [DEL‑####] START/END — both show up in Workfront (your screenshot). This stems from incomplete sanitization of “code” columns and NULLs.

Fix

In the export builder (where you assemble WF rows → XML):

Sanitize the deliverable code:

def safe_code(name:str, code:str|None):
    c = (code or "").strip()
    if not c or c.lower()=="nan":
        # fallback to slug of the deliverable name
        return re.sub(r"[^a-z0-9]+", "_", (name or "deliverable").lower()).strip("_")
    return c


Use safe_code() when generating [CODE] START / [CODE] END.

For the visible task name in Workfront, prefer deliverable display names for the parent and the component/L3 labels for children (we already normalize Component and Task_Label).

Also ensure the Project title at XML top uses the Step 3 “Project name” while Task row #1 is always “Project Summary”:

<Project><Name>…</Name></Project> ← write the Step 3 field

First task node <Task><Name>Project Summary</Name> … </Task>

(Earlier exports showed the project name twice or “Project from Scenario A”. The fix above guarantees separate values.)
