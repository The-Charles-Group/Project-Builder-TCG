1) Why the [DEL‑xxxx] START/END rows appear

During MSPDI export we intentionally inject two “anchor” tasks per deliverable—a START and an END—to make the dependency chain between components/deliverables deterministic after import into Workfront. Those anchors are created in the enrich_wbs_for_workfront(...) routine before we write <Task> XML. You can see the anchor objects built with names like "[{dcode}] START" / "[{dcode}] END" here (multiple copies of the same block exist in the compiled build):

That is why your Workfront grid shows rows such as [DEL‑0029] START and [DEL‑0029] END (and previously [nan] START/END when a deliverable code was missing in the data). We already added a guard (safe_code(...)) so you don’t see [nan] anymore; it falls back to a safe, unique slug of the deliverable name.

What we’ll change

You asked to stop showing those [DEL‑xxxx] labels. We’ll keep the anchors (they’re very helpful for stable schedules), but rename them to friendly milestone names and mark them as milestones so they’re visually lightweight in Workfront.
