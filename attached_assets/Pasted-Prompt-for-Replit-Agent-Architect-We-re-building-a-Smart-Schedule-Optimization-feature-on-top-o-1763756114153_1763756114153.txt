Prompt for Replit Agent & Architect

We’re building a “Smart Schedule Optimization” feature on top of our existing FastAPI app that generates Gantt timelines and Workfront/MS Project XML.

1. Goal

Add a final AI optimization pass that:

Takes the current schedule (deliverables, components, tasks, role-level tasks) generated by our existing logic.

Applies realistic PM reasoning (parallel work, dependencies, business rules) using GPT-5.1 Pro / Thinking.

Returns:

Updated Start / End dates

Updated durations (in days / hours)

Updated dependencies (predecessor links)

A natural-language explanation of what it changed and why.

We then:

Show the user a diff vs the baseline.

Let them accept/reject.

Export the AI-adjusted plan to Excel and XML (Workfront import).

2. Model requirements

For the optimization call, use OpenAI gpt-5.1-pro (or gpt-5.1-thinking`).

Keep any cheaper models (e.g. gpt-4.1-mini) for simple chat / helpers, but the schedule optimizer must use 5.1 Pro.

3. Data you should send to GPT-5.1 Pro

Create a compact JSON representation of the current plan. For each item:

{
  "project": {
    "name": "string",
    "start_date": "YYYY-MM-DD",
    "target_end_date": "YYYY-MM-DD | null",
    "working_calendar": {
      "workday_hours": 8,
      "weekends_off": true,
      "holidays": ["YYYY-MM-DD", "..."]
    }
  },
  "items": [
    {
      "id": "string",                 // internal id
      "wbs": "1.2.3",                 // deliverable/component/task hierarchy
      "name": "string",
      "level": 2,                     // 1=project, 2=deliverable, 3=component, 4=task, 5+=role-level
      "type": "summary|task|role",
      "role": "Copywriter | AM | ...",
      "planned_hours": 32,
      "duration_days": 5,
      "start": "YYYY-MM-DD",
      "end": "YYYY-MM-DD",
      "dependencies": ["id-123", "id-456"], // predecessors
      "service_department": "Strategy|Creative|...",
      "is_milestone": false
    }
  ]
}


You can derive this from whatever we already use to build the XML / spreadsheet.

4. System prompt for GPT-5.1 Pro

Use something like this as the system message:

You are a senior digital project manager and scheduling expert.
You receive a project plan with deliverables, components, tasks, and role-level tasks, including dates, durations, and dependencies.
Your job is to adjust the schedule realistically, not to invent new work.

Rules:

Do not add or remove items; only adjust dates, durations, and dependencies.

Respect the project working calendar (8h days, no weekends, holidays list).

Role-level tasks for different roles may run in parallel when realistic.
Do NOT make every task wait for the previous one unless it’s truly dependent.

Use dependencies to express true blocking relationships only.

Keep total planned hours per task unchanged. If you change duration, you’re changing how those hours are spread, not the total.

Try to keep within the user’s selected overall timeline if possible; if not, explain why.

Preserve the hierarchy implied by the WBS (1 = project, 2 = deliverable, 3 = component, 4 = task, 5+ = role task).

Output only valid JSON that matches the requested schema.

5. User message (what we send with each optimization request)

For each optimization call, send a user message like:

Here is the current baseline project schedule generated by our app.
Please adjust dates, durations, and dependencies to be realistic, following the rules in the system message.
Then return the updated schedule and an explanation of key changes.

BASELINE_JSON_GOES_HERE

6. Expected JSON response from GPT-5.1 Pro

Ask the model to return:

{
  "items": [
    {
      "id": "string",            // same as input id
      "start": "YYYY-MM-DD",
      "end": "YYYY-MM-DD",
      "duration_days": 5,
      "dependencies": ["id-123", "id-456"]  // updated predecessors
    }
  ],
  "explanation": {
    "summary": "Short summary of what changed overall.",
    "changes_by_group": [
      {
        "group_name": "Brand Positioning Strategy",
        "notes": "What changed in this group and why."
      }
    ],
    "risks_or_assumptions": [
      "Any assumptions the AI made about parallel work, approvals, etc."
    ]
  }
}

7. Backend integration steps

Add a new service function (e.g. optimize_schedule_with_ai(baseline_plan)) that:

Builds the baseline JSON.

Calls OpenAI gpt-5.1-pro with the system + user messages.

Parses the JSON response.

Merge results:

For each item id, update start/end/duration/dependencies in our internal data model.

UI changes:

Add a button: “AI Optimize Schedule”.

After the call, show a comparison:

Baseline vs AI dates

Baseline vs AI dependencies

The explanation text from explanation.summary and changes_by_group.

Export:

Ensure the XML and Excel exporters now use the AI-updated data if the user accepts the optimization.

Safety / fallbacks:

If the AI response is invalid or missing items, log and fall back to the baseline schedule.

Never write partial corrupt data.

8. Important constraints

Do not change pricing logic, hours calculations, or WBS generation already working in main.py.

The AI layer is optional and must sit on top of the existing static schedule logic.

All changes must preserve compatibility with existing XML imports into Workfront/MS Project.
