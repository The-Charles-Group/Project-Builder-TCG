Goal

The MSPDI <Project><Name> in the XML must equal the text typed in Step 3 → Project name (e.g., Casa‑Dragones‑Digital‑MKT‑RFP), not “Scenario A/B”.

The first task row must be a Project Summary task that also uses that same name.

Why this is needed: several of your recent XMLs still show <Name>Scenario A</Name> or Project from Scenario A even though the first task is the right name; Workfront then shows the scenario label in the header.
At the same time, your first task already appears as a summary row (see <Summary>1</Summary> on UID 1 with the correct project name).

A) Put the typed project name into <Project><Name>

In the MSPDI exporter (convert_excel_to_mspdi(...)) make sure we derive the title from the workbook (or accept it as a param) instead of the sheet name:

# after you load the sheet into df
project_title = None

# Prefer: the root WBS row (WBS_ID == "1")
if "WBS_ID" in df.columns and "Task_Name" in df.columns:
    root = df[df["WBS_ID"].astype(str).str.strip() == "1"]
    if not root.empty:
        t = str(root["Task_Name"].iloc[0]).strip()
        if t:
            project_title = t

# Fallback: explicit column if you keep one
if not project_title and "Project_Name" in df.columns:
    t = str(df["Project_Name"].dropna().astype(str).iloc[0]).strip()
    if t:
        project_title = t

# Final fallback: sheet label (Scenario A/B)
if not project_title:
    project_title = str(sheet_name).strip() or "Project"

# Write the header
SubElement(project, "Name").text = project_title


This replaces the old logic that used the sheet label (that’s why your header keeps saying “Scenario A/B”). The XMLs you sent show this earlier behavior clearly.

If you already pass project_name into the exporter from your export endpoint, you can simply do:

SubElement(project, "Name").text = (project_name or project_title)


Either approach is fine; the key is not to use the sheet name anymore.

B) Make the first row a Project Summary task (and keep it clean)

When you build the DataFrame for export (your WBS builder), ensure you always add the top row like this:

rows.append({
    "Project_Name": project_name,     # used elsewhere / CSV
    "WBS_ID": "1",
    "Parent_WBS_ID": "",
    "Task_Name": project_name,        # this is the visible summary row text
    "Planned_Hours": 0,
    "Start_Offset_Days": 0,
    "Duration_Days": 0,               # let Workfront roll up
    "Dependencies": ""
})


Then in convert_excel_to_mspdi(...), set summary semantics for that row:

is_root = str(row["WBS_ID"]).strip() == "1"
# ... write the task fields ...
SubElement(task, "Summary").text = "1" if is_root or has_children else "0"
if is_root:
    SubElement(task, "Work").text = "PT0M"
    SubElement(task, "Duration").text = "PT0M"   # Workfront/MS Project will roll up


Your current files already emit this first row with <Summary>1</Summary>, but they also carry a 1‑day duration (PT480M). Switching that to PT0M keeps the summary pure and prevents the spurious “1 day” you sometimes see on the project row. (Workfront will still display the rolled‑up start/finish). Compare your current root rows where <Summary>1</Summary> is set and the name is already the project name.
