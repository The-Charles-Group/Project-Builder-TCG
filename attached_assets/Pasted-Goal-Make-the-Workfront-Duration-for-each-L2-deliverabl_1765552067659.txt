Goal

Make the Workfront Duration for each L2 deliverable equal to the “Working duration (Mon–Fri)” shown in Step‑4 of the app.

In particular, for Brand Identity Development we want:

Start: 2026‑01‑05

Finish: 2026‑04‑02

Working span: 64 business days

XML <Duration>: PT30720M (64 × 480)

XML <Work>: PT18000M (300h)

XML <Units>: 0.5859375 (= 300h / (64d × 8h))

Step 1 – Ensure compression metadata is always available

The function compress_deliverable_timeline() already computes duration_business_days per deliverable:

info['duration_business_days'] = calculate_business_days_between(
    info['min_start'], info['max_end']
)


Action items:

In the timeline generation path (inside /api/ai/generate_timeline), make sure you call:

compressed_tasks, compression_metadata = compress_deliverable_timeline(
    timeline_tasks,
    project_start=project_start,
    buffer_work_days=...
)


Store compression_metadata into the scenario metadata that gets persisted and later used by:

Step‑4 Gantt

XML export

Example:

scenario["metadata"]["compression"] = compression_metadata


When exporting XML, pass that same compression_metadata into the XML export function so it’s available in the [XML EXPORT] block.

Step 2 – Use business days for deliverable <Duration> (no fallback for L2)

In the XML export code, you already have a branch for deliverables:

elif is_deliverable:
    SubElement(task, "Work").text = "PT0M"
    duration_days = None
    deliv_code = r.get("DeliverableCode", "")

    if compression_metadata and deliv_code:

        if comp_map and deliv_code in comp_map:

Right after that, you currently do a calendar fallback:

    # uses (finish_dt - start_dt).days -> calendar span


Change this behaviour:

For L2 deliverables, do not fall back to calendar span.
If there is no duration_business_days in compression_metadata, treat that as a bug and default to at least the Mon–Fri span:

if not duration_days or duration_days <= 0:
    # FINAL fallback: compute business days from Start/Finish
    start_str = uid_to_sched[r["UID"]]["Start"]
    finish_str = uid_to_sched[r["UID"]]["Finish"]
    start_dt = datetime.datetime.fromisoformat(start_str.replace('Z', '')).date()
    finish_dt = datetime.datetime.fromisoformat(finish_str.replace('Z', '')).date()
    duration_days = calculate_business_days_between(start_dt, finish_dt)


→ That way, L2 Duration is always in business days, never raw calendar ((finish - start).days).

Then keep the existing “clamp and multiply” lines:

duration_minutes = duration_days * 480
SubElement(task, "Duration").text = f"PT{duration_minutes}M"

Step 3 – Make Units & Work consistent with that duration

For each L2 deliverable row, you already know:

planned_hours

duration_business_days (64 for Brand Identity)

project hours per day = 8

When creating assignments for the L2 task (TaskUID 2):

Set Work in minutes:

work_minutes = int(round(planned_hours * 60))
SubElement(assignment, "Work").text = f"PT{work_minutes}M"


Compute units from Work and Duration:

duration_minutes = duration_days * 480
units = work_minutes / duration_minutes  # e.g. 18000 / 30720 = 0.5859375
SubElement(assignment, "Units").text = str(units)


This guarantees that Workfront’s own formula recomputes the same duration:

Duration = Work / (Units × 60) = duration_days

(Workfront treats Units as fraction of an 8‑hour day when MinutesPerDay = 480.)

5. Quick human summary you can tell the team

Effort days = hours ÷ 8 – a pure “how much work” number.

Working duration = Mon–Fri span between start and end dates – currently 64 days.

Workfront Duration is controlled by the <Duration>, <Work>, and <Units> fields in your XML.

Your app’s Gantt and compression logic are already using 64 working days; the mismatch comes from the XML still writing 87 calendar days into <Duration> when compression_metadata isn’t picked up.

The fix is to:

Always pass compression_metadata into export,

Always use duration_business_days for L2 deliverables when writing <Duration>,

Ensure <Work> and <Units> are computed from that same duration.
