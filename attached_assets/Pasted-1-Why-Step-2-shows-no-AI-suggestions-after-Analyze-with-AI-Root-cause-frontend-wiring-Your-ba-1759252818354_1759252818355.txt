2) Why the XML import is rejected by Workfront (and how to fix)

I inspected your latest XML (…2025‑09‑30 01.04PM EST.xml). Two specific issues stand out.

A. Summary detection bug (main reason import fails)

In convert_excel_to_mspdi you changed the roll‑up mapping to be UID‑based, but the “is this a summary task?” check still compares WBS strings to a set of UIDs:

# mapping is now UID→children (you build summary_set from UID keys)
summary_set = set(children_by_parent.keys())

# BUG: still testing WBS against a UID set
is_summary = r["WBS"] in summary_set


Result: every task is treated as a leaf, so the exporter writes Work/Duration/ConstraintType even on summary tasks (including the project summary). You can see that in your XML—the top task (summary) has ConstraintType and ConstraintDate, which should never be present on summaries and can cause Workfront/MS Project to choke.

Fix (backend):

Replit, in convert_excel_to_mspdi where you create tasks, replace the summary check:

# OLD
is_summary = r["WBS"] in summary_set

# NEW
is_summary = r["UID"] in summary_set


Keep the “only set Work/Duration/Constraint* for non-summary” logic exactly as you already have it—just make sure is_summary is computed by UID. (That one-line change aligns the new UID roll‑up with the summary check.)

B. Project Name mismatch (“Project from Scenario A”)

The <Project><Name> is hard-coded from the Excel sheet name:

SubElement(project, "Name").text = f"Project from {sheet_name}"


That’s why Workfront shows “Project from Scenario A.” You set project_name elsewhere, but this exporter ignores it.

Fix (backend):

Replit, let convert_excel_to_mspdi accept a project_name parameter and set <Name> from it:

def convert_excel_to_mspdi(..., project_name=None, sheet_name="Scenario A", ...):
    ...
    SubElement(project, "Name").text = (project_name or f"Project from {sheet_name}")


Then pass project_name from the export endpoints (/api/export_xml, /api/export_workbook_xml). The endpoints already compute project_name from the UI/file title—just thread it through to the converter.

C. (FYI) OutlineLevel values

You compute OutlineLevel from WBS depth (count('.') + 1), so the top task is 2 when the first WBS row is 1.0. That’s acceptable and not the cause of the import failure by itself. The real problem is the summary/leaf confusion described above.

5) Why durations show as hours (minutes in XML) vs days

This is expected. MSPDI stores duration and work in minutes (PT####M). Workfront displays durations as days because it applies its 8‑hour business calendar. Your XML already sets MinutesPerDay=480 and calendar blocks (8–12 & 13–17). That’s correct and consistent.
