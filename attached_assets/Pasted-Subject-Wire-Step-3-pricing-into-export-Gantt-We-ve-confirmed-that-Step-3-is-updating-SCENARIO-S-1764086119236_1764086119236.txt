Subject: Wire Step 3 pricing into export / Gantt

We’ve confirmed that Step 3 is updating SCENARIO_STORE correctly, but the export is still using stale data.

Concrete example from the “St. Regis” scenario:

Step 3 UI:

Brand Positioning Strategy → 100 hours, $210/hr, $21,000 price

Retainers total: $111,870

Project Scenario total: $212,880

Exported XML:

Same task’s <Assignment> still has 48 hours (Work="PT2880M") and $9,360 (Cost="9360.00").

Retainers total: $100,230

Grand total: $201,240 (old value)

So Step 3 + the breakdown card are reading the updated scenario, but the export (and the “Grand Total” banner) are reading from an older data structure built before Step 3 sync.

What needs to change
1. Find where export reads data

Locate the functions that build the export:

build_ms_project_file(...) (or equivalent)

build_wbs_with_pricing(...) / WBS/timeline builder

Identify exactly what they use as input right now — it’s likely a precomputed WBS or original scenario snapshot.

2. Wire export to use the merged scenario

For export/Gantt building, we should always:

scenario = SCENARIO_STORE[session_id]["scenario"]
scenario = _recompute_totals(scenario)


after merge_scenario_from_sync(session_id) has been applied.

Key point: do not use an earlier snapshot or parallel WBS structure as the source of truth for hours/rates/prices. Export should be built from the same scenario object that Step 3 and the breakdown card use.

3. Fix Work/Cost calculations for assignments

When building tasks/assignments, use helpers that read from the scenario items:

Hours: get_hours_from_item(item) (handles Planned_Hours / planned_hours)

Rate: get_rate_from_item(item) (handles Rate_USD, rate_usd, etc.)

Total price: get_price_from_item(item) (or equivalent canonical price_usd logic)

For each deliverable:

hours = get_hours_from_item(item)      # float hours
rate  = get_rate_from_item(item)
price = get_price_from_item(item)      # usually price_usd

# For XML:
work_minutes = int(hours * 60)
cost = price

# e.g.
<Work>PT{work_minutes}M</Work>
<Cost>{cost:.2f}</Cost>


After the fix, for Brand Positioning Strategy in my test:

Work should be PT6000M (100 hours)

Cost should be 21000.00

4. Activate monthly WBS expansion for retainers

For items where:

billing_cadence == "monthly" and

retainer_months > 0 (or retainer["months"] > 0)

the WBS builder should:

Keep the parent deliverable row (0 hours, summary).

Call expand_retainer_into_months(parent_row, months, project_start_date) (or equivalent) to create one child per month:

WBS IDs X.1, X.2, …

Names like "Brand Positioning Strategy – February", "– March", etc.

Start/End dates confined to that month.

Monthly hours and cost that match the pricing math.

Right now, exports still show only a single row for retainers, so this monthly expansion isn’t being used.
