You’re right—the Service_Department is there, but the A–E columns aren’t showing up first. Here’s a quick, drop‑in fix that (1) guarantees the five columns exist on every row and (2) forces them to the leftmost positions in both single‑scenario and two‑tab exports.

Your current export writes the WBS but doesn’t reindex columns; so Excel shows Project_Name, WBS_ID, … first and your A–E fields are either missing or buried to the right. The patch below standardizes and reorders them for every export.

1) Add a helper to enforce v3 A–E as the first five columns

File: main.py

# Place near other export helpers
V3_AE_ORDER = ["Row_ID", "Deliverable_Code", "Task_Code", "Service_Department", "Deliverable"]

def _ensure_v3_ae_columns(df: pd.DataFrame) -> pd.DataFrame:
    # Create columns if missing
    for c in V3_AE_ORDER:
        if c not in df.columns:
            df[c] = ""
    # Reorder so A–E are leftmost
    rest = [c for c in df.columns if c not in V3_AE_ORDER]
    return df[V3_AE_ORDER + rest]

2) Use it in /api/export (single scenario)

Replace the tail of your /api/export route (right before writing the file) with:

df = build_wbs_dataframe_from_scenario(payload.scenario or {}, project_name)

# <<< force A–E to the left and guarantee presence
df = _ensure_v3_ae_columns(df)

# then write CSV/XLSX as you already do


(If your /api/export currently builds rows directly, switch to your build_wbs_dataframe_from_scenario(...) first, then apply _ensure_v3_ae_columns(df).)

3) Use it in /api/export_workbook (two tabs, one file)

Do the same for each sheet:

dfA = build_wbs_dataframe_from_scenario(payload.scenario_a or {}, project)
dfB = build_wbs_dataframe_from_scenario(payload.scenario_b or {}, project)

dfA = _ensure_v3_ae_columns(dfA)
dfB = _ensure_v3_ae_columns(dfB)

with pd.ExcelWriter(out_name, engine="openpyxl") as xw:
    dfA.to_excel(xw, sheet_name=_safe_sheet_name(payload.sheet_name_a or "Scenario A"), index=False)
    dfB.to_excel(xw, sheet_name=_safe_sheet_name(payload.sheet_name_b or "Scenario B"), index=False)

4) Where A–E values come from (so they actually populate)

Make sure your WBS builder fills these fields per row (you already have most of this):

Row_ID → from v4/v4b All_Task_Rows (Row_ID). For deliverable/component rows use "" (blank).

Deliverable_Code → from the deliverable being exported (e.g., PAID_SOCIAL_ADS) on every row under it.

Task_Code → from v4/v4b (Task_Code / Task Code / Task_Code_L1 …). For deliverable/component rows use "".

Service_Department → “majority by hours” selection from v4/v4b under that scope (deliverable/component/task).

Deliverable → the human‑readable deliverable name from Deliverable_Index.

If any of those columns are named differently in your v4/v4b sheet, keep the small normalizers we added earlier (they map synonyms like Service Department → Service_Department, Task Code → Task_Code, etc.), so these values actually populate.
