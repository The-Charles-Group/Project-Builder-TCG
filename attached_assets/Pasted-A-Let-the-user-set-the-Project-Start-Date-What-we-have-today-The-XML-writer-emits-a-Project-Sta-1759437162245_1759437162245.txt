B. Show durations as days in Workfront

What we have today

Project header has <DurationFormat>7</DurationFormat> (project‑level), and all task <Duration>s are emitted in minutes (PT960M = 2 days given 480 min/day). Workfront is currently showing “hours” for many tasks even though earlier imports displayed “days.” The header exists, but we don’t emit per‑task DurationFormat, and many parent rows aren’t flagged as summaries.

Change

Emit per‑task DurationFormat = Days
In the task writer loop inside convert_excel_to_mspdi(...), add:

SubElement(task, "DurationFormat").text = "7"  # Days (MSPDI enum)


(We already set project‑level to 7; setting it at the task level removes ambiguity for Workfront.)

Mark true summaries
Rows that have children must be Summary=1 and shouldn’t carry their own Work/Duration—let Workfront roll them up. You can see some “parent‑like” rows in your XML are not summaries (Summary>0</Summary> appears only on the very top row). Fixing this stabilizes how durations display.

C. Make app timeline duration = Workfront duration

This is the heart of the 87‑days vs 446‑days discrepancy.

Why it happens

In MSP/Workfront the identity is Duration = Work / Units (for Fixed Units tasks).

Our XML currently doesn’t set a task Type. The default is treated as Fixed Units, and we also export fractional assignment units (e.g., 0.31, 0.44). Example from the export: Work PT4920M with Units ≈ 0.31 yields Duration PT15840M — that’s 33 days at 8h/day, much longer than your Step 4 plan. You can see the fractional Units in Assignments for Scenario A.

Fix

Export leaf tasks as Fixed Duration so the Duration you computed in Step 4 becomes canonical, and let “Units” float to whatever value makes Work = Duration × Units.

Set task type to Fixed Duration
In the task writer loop (leaf tasks only), add:

SubElement(task, "Type").text = "1"          # 1 = Fixed Duration
SubElement(task, "IsEffortDriven").text = "0" # avoid effort-driven recalcs


Write Duration from Step 4
Keep using your Step 4 Duration_Days → PT{days*480}M (minutes). We already write minute durations; just ensure we’re writing the Step 4 value for leaves and not letting it be recomputed on import.

Compute assignment Units consistently
For each leaf task:

work_min = planned_hours * 60
dur_min  = duration_days * 480
units    = 0 if dur_min == 0 else work_min / dur_min   # may be >1.0; that’s ok
SubElement(assignment, "Units").text = str(units)
SubElement(assignment, "Work").text  = f"PT{work_min}M"


Because the task is Fixed Duration, Workfront will keep your duration and set resource loading to the computed Units rather than stretching the dates. In your current XML, fractional units under “Fixed Units” are what balloon durations (see the 0.3106 units example).

Use “ASAP” constraints everywhere except the project’s first task
We currently stamp every task with ConstraintType>4</ConstraintType> and a ConstraintDate at its start—pinning tasks unnecessarily. Switch non‑root tasks to As Soon As Possible and rely on predecessors + the calendar for placement. Only the very first task needs a “Must Start On” at project_start_iso. That keeps Workfront’s scheduler from adding artificial lags. (You already serialize the FS predecessor links correctly.)
