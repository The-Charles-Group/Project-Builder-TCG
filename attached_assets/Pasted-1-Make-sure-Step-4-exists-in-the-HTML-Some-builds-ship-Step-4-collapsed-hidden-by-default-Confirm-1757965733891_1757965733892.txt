1) Make sure Step 4 exists in the HTML

Some builds ship Step 4 collapsed/hidden by default. Confirm you have a container like:

<section id="step4" style="display:none">
  <h3>Step 4 — Timeline</h3>
  <div id="timeline-controls">
    <button type="button" data-timeline-sel="A" id="tl-sel-A">Scenario A</button>
    <button type="button" data-timeline-sel="B" id="tl-sel-B">Scenario B</button>
    <button type="button" data-timeline-sel="C" id="tl-sel-C" style="display:none">Scenario C</button>
  </div>
  <table id="tl-table" class="table-compact" style="width:100%">
    <thead>
      <tr><th>Deliverable</th><th>Start</th><th>End</th><th>Duration (days)</th></tr>
    </thead>
    <tbody id="tl-body"></tbody>
  </table>
</section>


(If your Step 4 block uses a different “hidden” mechanism, the JS below toggles it either way.)

2) After Build Scenarios A & B, auto‑show Step 4 and render the timeline

At the end of your existing success path for the Build Scenarios A & B click handler (right after you save appState.scenarios / draw the A & B cards), add:

function showStep4(letter = 'A') {
  // reveal Step 4
  const s4 = document.getElementById('step4');
  if (s4) {
    s4.style.removeProperty('display');    // handles display:none
    s4.classList.remove('hidden');         // handles .hidden class
  }
  // show Scenario C button if C exists
  const hasC = !!(window.appState?.scenarios?.C?.items?.length);
  const btnC = document.getElementById('tl-sel-C');
  if (btnC) btnC.style.display = hasC ? '' : 'none';

  // render and scroll
  renderTimeline(letter);                  // uses the renderer we added earlier
  s4?.scrollIntoView({ behavior: 'smooth', block: 'start' });
}

async function onBuildScenariosAB() {
  // ...your existing fetch to /api/build and UI updates...
  window.appState = window.appState || {};
  window.appState.scenarios = data.scenarios;       // A & B set here
  // NEW: jump to Step 4 and show Scenario A timeline immediately
  showStep4('A');
}


If your handler name differs, paste the showStep4 helper and call it at the end of that handler.

Why this is needed: v2.3 builds/prices A & B correctly, but doesn’t automatically initialize Step 4. The scheduler (build_schedule(...)) is already in place; we just need to render & navigate to it.

3) When you Build Scenario C (Upsell), jump to Step 4 on C

At the end of your Scenario C handler (after saving appState.scenarios.C and drawing the C card), add:

async function onBuildScenarioC() {
  // ... your existing fetch to /api/build_scenario_c ...
  window.appState.scenarios.C = res.C;
  // show Step 4 and render C; also make the “Scenario C” button visible
  const btnC = document.getElementById('tl-sel-C');
  if (btnC) btnC.style.display = '';
  showStep4('C');
}

4) Allow clicking A/B/C in Step 4 to switch the view

If you haven’t already wired the toggle, keep this global click listener:

document.addEventListener('click', (e) => {
  const btn = e.target.closest('[data-timeline-sel]');
  if (!btn) return;
  renderTimeline(btn.dataset.timelineSel);  // 'A' | 'B' | 'C'
});


The renderTimeline(letter) function we added earlier reads from appState.scenarios[letter] and rebuilds the table.

5) Quick sanity checks (15 seconds)

In the console after clicking Build Scenarios A & B:

appState?.scenarios?.A?.items?.length   // should be > 0
appState?.scenarios?.B?.items?.length   // should be > 0


If Step 4 doesn’t appear, run:

showStep4('A');


That should reveal the section, render the timeline, and scroll to it.
