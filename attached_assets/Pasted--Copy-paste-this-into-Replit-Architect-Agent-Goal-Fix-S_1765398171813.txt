Goal
Fix Step 3 so that:

Both Project Scenario and Deliverable Pricing Details are pre‑populated when the user clicks Proceed to Pricing from Step 2.

Any edits in Pricing Details (deliverable hours, component hours, rates, cadence/type) are written back into the canonical scenario stored in the backend.

The backend already has a unified scenario store and sync endpoint:

SCENARIO_STORE and _CURRENT_SCENARIOS

Real‑time sync: /api/scenario/sync and merge_scenario_from_sync(session_id)

Pricing breakdown: /api/pricing/rebuild_breakdown (now uses get_hours_from_item())

The remaining bugs are on the frontend data flow:

Step 3 initial load does not always hydrate both panels from the backend scenario.

The “Build Scenario” button on Step 3 still rebuilds from Step 2 / default data, overwriting Step 3 edits, which is why Workfront sometimes shows 300h while the Pricing screen shows 308h.

We must treat SCENARIO_STORE[session_id]["scenario"] as the single source of truth for all pricing + timeline + export logic.

async function initPricingStep() {
  const sessionId = window.SESSION_ID;
  if (!sessionId) {
    console.error("No SESSION_ID on Step 3");
    return;
  }

    method: "POST",
    headers: { "Content-Type": "application/json" },

  });

  const data = await scenarioRes.json();
  // data should include scenarioA / scenario(s); pick A or default
  const scenario = data.scenarioA || data.scenario || data[0]?.scenario;
  if (!scenario || !scenario.items || !scenario.items.length) {

    window.SCENARIO_A = built.scenarioA || built.scenario;
  } else {

  // 2) Rebuild pricing UI from backend scenario

Task 3.2 – Keep parent deliverable hours in sync

Create a utility that recomputes the parent deliverable row as the sum of its components, and also updates the scenario item for the parent:

function recalcDeliverableTotalsInUi(deliverableCode) {
  if (!window.SCENARIO_A || !window.SCENARIO_A.items) return;

  const items = window.SCENARIO_A.items;
  const parent = items.find(
    it => it.deliverable_code === deliverableCode && !it.component_code && !it.component
  );
  const children = items.filter(
    it => it.deliverable_code === deliverableCode && (it.component_code || it.component)
  );

  const total = children.reduce((sum, it) => {
    const h = Number(it.hours ?? it.Planned_Hours ?? it.planned_hours ?? 0);
    return sum + (isNaN(h) ? 0 : h);
  }, 0);

  if (parent) {
    setItemHours(parent, total); // ensures parent item matches components
  }

  // update the Project Scenario table cell
  const row = document.querySelector(
    `.project-scenario-row[data-deliverable-code="${deliverableCode}"]`
  );
  if (row) {
    const cell = row.querySelector(".scenario-hours-cell");
    if (cell) cell.textContent = total.toFixed(0);
  }
}


This is what should prevent the “3 extra hours magically added” behaviour: parent hours become exactly the sum of components, and those are what get synced.

Task 4.2 – Implement syncScenarioToBackend()

Re‑use the existing backend sync endpoint /api/scenario/sync. On the frontend, create:

window.SCENARIO_SYNC_STATE = window.SCENARIO_SYNC_STATE || {
  version: 0,
  lastServerVersion: 0,
  checksum: ""
};

async function syncScenarioToBackend() {
  const sessionId = window.SESSION_ID;
  if (!sessionId || !window.SCENARIO_A) return null;

  const payload = {
    session_id: sessionId,
    client_version: window.SCENARIO_SYNC_STATE.version || 0,
    last_server_version: window.SCENARIO_SYNC_STATE.lastServerVersion || 0,
    scenario: window.SCENARIO_A,
    selections: {}, // if you track row selections, pass them here
    timestamp: Date.now(),
    checksum: ""    // optional, leave blank for now
  };

  const res = await fetch("/api/scenario/sync", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(payload)
  });

  const data = await res.json();

  // Update sync state
  window.SCENARIO_SYNC_STATE.version = data.serverVersion;
  window.SCENARIO_SYNC_STATE.lastServerVersion = data.serverVersion;

  if (data.hasChanges && data.scenario) {
    // server is authoritative
    window.SCENARIO_A = data.scenario;
  }

  return data;
}
