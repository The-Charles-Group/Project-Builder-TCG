Fix (backend only — no frontend changes needed)

Apply the three small patches below in build_wbs_with_pricing(...). They’re defensive, so they cover both AI and manual flows.

Patch 1 — Resolve scenario_col once and reuse it everywhere

Before (deliverable loop):

scen_col = d.get("scenario_col", "MED_LOW")
included = [str(x) for x in d.get("included_task_groups", [])]


After:

# Resolve scenario_col from item; if missing/invalid, derive from complexity & tier
scen_col = d.get("scenario_col")
if not scen_col or scen_col not in DB.all_rows.columns:
    scen_col = DB.scenario_hours_col(d.get("complexity", "Advanced"),
                                     d.get("tier", "T2_MediumVolume"))
included = [str(x) for x in d.get("included_task_groups", [])]


This makes sure all downstream calls that use scen_col (components, task‑group splits, role allocations) work for AI‑suggested items.

Do the same in the pre‑grouping “enrich items” pass at the top of the function (where we first compute departments): resolve scen_col exactly the same way before asking for a department.

Patch 2 — Use v3 department inference first (no scenario_col dependency)

Before (both in the “enrich items” pass and when writing the deliverable row):

dept = DB.service_dept_for_deliverable(dcode, tgs, scen_col) or "Other"
...
svc_deliv = DB.service_dept_for_deliverable(dcode, tg_order, scen_col)


After:

# Prefer v3 (doesn’t need scen_col), then fall back to v2
dept = (DB.service_department_for_deliverable(dcode, tgs)
        or DB.service_dept_for_deliverable(dcode, tgs, scen_col)
        or "Other")

...
svc_deliv = (DB.service_department_for_deliverable(dcode, tg_order)
             or DB.service_dept_for_deliverable(dcode, tg_order, scen_col))


And for components & tasks, make the same change:

svc_comp = (DB.service_department_for_component(dcode, comp, tg_in_comp)
            or DB.service_dept_for_component(dcode, comp, tg_in_comp, scen_col))

# when writing role rows under a task:
svc_task = DB.service_department_for_task(dcode, comp, tg)  # prefer v3


v3 versions don’t require scenario_col, so grouping won’t collapse into “Other” when items arrive from AI.
