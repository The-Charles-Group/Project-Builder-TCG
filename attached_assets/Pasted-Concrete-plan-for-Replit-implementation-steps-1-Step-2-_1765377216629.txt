Concrete plan for Replit / implementation steps
1. Step 2 → Step 3: populate both panels on initial load

Goal: When you click Proceed to Pricing, Step 3 should:

Get the working scenario for the current session.

Run rebuildPricingFromBackend() once.

Render both panels from that single result.

Implementation sketch (front‑end JS):

In whatever file drives Step 3 (often something like static/step3_pricing.js):

// Runs when Step 3 loads
async function initPricingStep() {
  const sessionId = window.SESSION_ID;

  // 1. Ask backend for the current scenario (built in Step 2)
  const resp = await fetch('/api/scenarios', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      session_id: sessionId,
      reset: false  // IMPORTANT: reuse working scenario, don't rebuild baseline
    })
  });

  const data = await resp.json();
  if (!data.ok) {
    console.error('Failed to load scenario:', data);
    return;
  }

  const scenarioA = data.scenarios.A;
  window.SCENARIO_A = scenarioA; // keep in memory for edits

  // 2. Build pricing breakdown + tiles from backend
  // This function already:
  // - syncs scenario to /api/scenario/sync
  // - calls /api/pricing/rebuild_breakdown
  // - updates both panels + summary cards
  await window.rebuildPricingFromBackend(window.SCENARIO_A);
}

// Call this when Step 3 page mounts
document.addEventListener('DOMContentLoaded', () => {
  initPricingStep().catch(console.error);
});


And from Step 2’s Proceed to Pricing button, you don’t need to re‑build the scenario; you can just navigate to Step 3. Step 3 will pick up whatever set_baseline_and_scenario stored for this session.

If you really want to force a fresh baseline rebuild at that moment, you can pass reset: true here once, but then you must not rebuild again when Step 3 loads or you’ll keep wiping any edits.

2. Make Pricing Details edits actually update the scenario

Right now the Pricing Details table is just a view over the scenario. We need to turn it into an editor that writes back to window.SCENARIO_A before calling rebuildPricingFromBackend.

Key idea:
Each row in “Deliverable Pricing Details” should be mapped to one or more items in scenario.items via Deliverable_Code + Component (or whatever keys you’re already using). Then, when the user changes hours/rate:

Update Planned_Hours / Rate_USD / Price_USD on the matching scenario item(s).

Mark the scenario as “dirty”.

Let the user click Update Pricing to push that to the backend & recalc.

Example wiring for a single component row:

let pricingDetailsDirty = false;

// Called on blur/change of an Hours input in Pricing Details
function onPricingDetailHoursChange(deliverableCode, componentName, newHoursStr) {
  const hours = parseFloat(newHoursStr) || 0;
  if (!window.SCENARIO_A || !Array.isArray(window.SCENARIO_A.items)) return;

  // Find the matching scenario item
  const item = window.SCENARIO_A.items.find(i =>
    i.Deliverable_Code === deliverableCode &&
    i.Component === componentName
  );
  if (!item) return;

  item.Planned_Hours = hours;

  const rate = item.Rate_USD || item.rate_usd || window.DEFAULT_BILLABLE_RATE_USD;
  item.Price_USD = Math.round(hours * rate * 100) / 100;

  pricingDetailsDirty = true;
}

// Similar handler for rate changes
function onPricingDetailRateChange(deliverableCode, componentName, newRateStr) {
  const rate = parseFloat(newRateStr) || 0;
  if (!window.SCENARIO_A || !Array.isArray(window.SCENARIO_A.items)) return;

  const item = window.SCENARIO_A.items.find(i =>
    i.Deliverable_Code === deliverableCode &&
    i.Component === componentName
  );
  if (!item) return;

  item.Rate_USD = rate;
  const hours = item.Planned_Hours || 0;
  item.Price_USD = Math.round(hours * rate * 100) / 100;

  pricingDetailsDirty = true;
}


You would hook these to the <input> elements in the Pricing Details table (e.g. via onchange="onPricingDetailHoursChange(...)").

3. Add an Update Pricing button in the Pricing Details panel

Add a button at the bottom of the “Deliverable Pricing Details” box:

<button id="update-pricing-details" class="btn btn-primary">
  Update Pricing
</button>


Wire it up to use the existing backend‑synced flow:

document.getElementById('update-pricing-details')
  .addEventListener('click', async () => {
    if (!pricingDetailsDirty) {
      // Nothing changed, no need to hit backend
      return;
    }

    if (!window.SCENARIO_A) return;

    try {
      // This will:
      // 1. sync SCENARIO_A → /api/scenario/sync
      // 2. call /api/pricing/rebuild_breakdown
      // 3. update:
      //    - Project Scenario panel
      //    - Deliverable Pricing Details
      //    - summary tiles (One-Time, Retainer, Grand Total)
      await window.rebuildPricingFromBackend(window.SCENARIO_A);

      pricingDetailsDirty = false;
    } catch (err) {
      console.error('Error updating pricing details', err);
      // Optionally show a toast to the user
    }
  });


Under the hood, rebuildPricingFromBackend will call /api/pricing/rebuild_breakdown, which:

Uses get_working_scenario(session_id) to get your newly updated scenario. 

12:09:25 - step 3 component box

Recomputes totals via _recompute_totals. 

12:09:25 - step 3 component box

Updates SCENARIO_STORE[session_id] (so the Gantt & exports see the new totals).

So you don’t have to be “smart” about partial recalcs; the backend already recomputes the whole picture from the updated scenario.

4. Confirming Gantt + exports stay in sync

Once the Scenario object is updated and stored via update_working_scenario / syncScenarioToBackend:

Step 4 Gantt: when tasks are adjusted, endpoints like /api/timeline/update_tasks_batch call get_working_scenario(session_id) and _recompute_totals, then write back via update_working_scenario. 

12:09:25 - step 3 component box

XML / XLSX / CSV / PDF exports: the export logic uses the same scenario rows, mapping Price_USD / price_usd → FixedCost etc, and uses the standard rates for resources. 

12:09:25 - step 3 component box

So as long as all Step 3 edits go through rebuildPricingFromBackend (which syncs the scenario), your hours & prices will be consistent everywhere.

What to tell the Replit agent

You can basically paste them this checklist:

On Step 3 load (DOMContentLoaded), call a new initPricingStep() that:

POSTs to /api/scenarios with { session_id, reset: false }.

Stores the returned scenarios.A in window.SCENARIO_A.

Calls await window.rebuildPricingFromBackend(window.SCENARIO_A).

In Deliverable Pricing Details, make the input handlers update window.SCENARIO_A.items (fields Planned_Hours, Rate_USD, Price_USD) and set a pricingDetailsDirty flag.

Add an Update Pricing button in the Pricing Details panel that:

If pricingDetailsDirty is true, calls await window.rebuildPricingFromBackend(window.SCENARIO_A).

Resets pricingDetailsDirty = false on success.

Do not do any local-only math for the summary tiles; always render them from the /api/pricing/rebuild_breakdown response so One‑Time, Retainer, and Grand Total always match the working scenario.
