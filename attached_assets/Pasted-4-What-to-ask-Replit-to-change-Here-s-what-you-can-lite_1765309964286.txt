B. Replace Save & View Totals with Build Scenario

Right now there is:

A “Save & View Totals” button that calls the old calc path.

An “Update Pricing” flow that Replit wired to:

syncScenarioToBackend() → /api/scenario/sync

rebuildPricingFromBackend() → /api/pricing/rebuild_breakdown

Ask them to:

Delete the Save & View Totals button from the UI.

No click handler, no call to /api/pricing/rebuild_breakdown from there.

Move the canonical pricing flow onto the “Build Scenario” button.

In pseudo-code:

async function handleBuildScenarioClick() {
  const scenario = getLocalScenario();        // whatever the UI is editing

  // 1) Sync to backend (SCENARIO_STORE)
  await syncScenarioToBackend(scenario);      // POST /api/scenario/sync

  // 2) Get authoritative breakdown + totals from backend
  const { breakdown, summary } =
    await rebuildPricingFromBackend(scenario); // POST /api/pricing/rebuild_breakdown

  // 3) Update UI from backend response
  applyBreakdownToUI(breakdown, summary);     // cards + table
}


syncScenarioToBackend should send { session_id, scenario, client_version, ... } to /api/scenario/sync, as they’re already doing.

rebuildPricingFromBackend should call /api/pricing/rebuild_breakdown with { session_id }, not recompute totals only on the client.

Make this same function the only way to refresh totals.

If there is still an “Update Pricing” button in the Pricing Details tab, have it call the same handler as the new “Build Scenario” button, or simply remove “Update Pricing” and keep only “Build Scenario”.

Result:

Any change in the Pricing Details grid → click Build Scenario → backend synced → cards and grand total updated from backend, exactly once, through one codepath.
