4) Make your real analyzer run in the background

If today you loop over candidates and call your GPT‑5 function for each (as in your ai_planner_agencydb.py code), extract that logic into a single coroutine that processes one batch and return it by reference in the job start payload:

# ai_planner_agencydb.py (example)
from openai import AsyncOpenAI
client = AsyncOpenAI()

async def batch_analyze_candidates(batch: list[dict], tier: str) -> list[dict]:
    """
    Convert your existing per‑candidate GPT‑5 call into a per‑batch function.
    Return a list of per‑candidate results.
    """
    out = []
    for item in batch:
        messages = [
            {"role": "system", "content": "You are an agency producer. Return strict JSON."},
            {"role": "user", "content": f"Analyze: {item['rfp']}"}
        ]
        resp = await client.responses.create(
            model={"mini":"gpt-5-mini","thinking":"gpt-5","pro":"gpt-5-pro"}[tier],
            input=messages,
            reasoning={"effort": {"mini":"low","thinking":"medium","pro":"high"}[tier]},
            max_output_tokens=1500
        )
        out.append({"id": item["id"], "result": resp.output_text})
    return out


Then start jobs with "analyzer": "ai_planner_agencydb.batch_analyze_candidates".

5) Tune runtime without code changes (env vars)

The job runner uses sensible defaults that you can adjust via environment variables:

Variable	Meaning	Default
AI_MAX_CONCURRENCY	How many batches to run in parallel	3
AI_CALL_TIMEOUT	Per OpenAI call timeout (sec)	50
AI_WALL_TIMEOUT	Whole job cutoff (sec)	900
AI_TIER	Default compute tier	thinking
APB_BATCH_MINI / APB_BATCH_THINKING / APB_BATCH_PRO	Batch size per tier	150 / 90 / 45

These values keep each OpenAI call under ~50s and keep HTTP threads free, so the site stays reachable.

7) Keep GPT‑5 calls correct & fast (recap)

Use Responses API for GPT‑5 (gpt-5, gpt-5-pro, gpt-5-mini).

Set compute with reasoning={"effort": "low|medium|high"} (mini/thinking/pro).

Prefer Structured Outputs (JSON Schema or Pydantic) to avoid slow re‑parsing/repairs.

Cap max_output_tokens realistically for the schema you need (don’t always send 2200).

Never run a multi‑minute loop inside a request handler—offload to a job.
