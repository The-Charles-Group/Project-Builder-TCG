The POST export you have explicitly sets Content‑Disposition: attachment; filename="..." (this forces a download)

Safe build 11.04.25

】. Most browsers will happily render XML inline when navigated to directly (especially if you trigger with window.open()).

Two quick remedies (you can do either or both):

Add the header and use a neutral content type in the GET routes:

return FileResponse(
    final_xml,
    filename=os.path.basename(final_xml),
    media_type="application/octet-stream",  # <- makes the browser treat it as a download
    headers={"Content-Disposition": f'attachment; filename="{os.path.basename(final_xml)}"'}
)


In the frontend, avoid window.open(...) for downloads. Instead use an <a download> link or fetch the file and trigger a Blob download—those don’t open a new tab.
