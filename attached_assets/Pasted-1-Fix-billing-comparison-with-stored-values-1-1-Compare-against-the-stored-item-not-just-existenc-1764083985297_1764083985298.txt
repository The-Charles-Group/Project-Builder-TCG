1. Fix billing comparison with stored values
1.1. Compare against the stored item, not just existence

In the sync route, before you touch the incoming scenario:

store_entry = SCENARIO_STORE.get(session_id, {})
old_scen = (store_entry.get("scenario") or {})
old_items_by_id = {
    (i.get("id") or i.get("Row_ID")): i
    for i in old_scen.get("items", [])
}


Define:

def cadence_changed(old_item: dict | None, new_item: dict) -> bool:
    if not old_item:
        return True
    fields = ["billing_cadence", "cadence_units", "cadence_price"]
    for f in fields:
        old = old_item.get(f)
        new = new_item.get(f)
        # normalize to string so "12" vs 12 compare equal
        if (old is None) and (new is None):
            continue
        if str(old) != str(new):
            return True
    return False

def monthly_price_changed(old_item: dict | None, new_item: dict) -> bool:
    if not old_item:
        return "monthly_price" in new_item
    if "monthly_price" not in new_item:
        return False
    try:
        old = float(old_item.get("monthly_price") or 0)
        new = float(new_item.get("monthly_price") or 0)
    except (TypeError, ValueError):
        return True
    return abs(old - new) > 0.0001

2. Update totals calculation for old items
2.1. Backward-compatible rate lookup

Put this in a shared helpers section:

def get_rate_from_item(item: dict) -> float:
    for key in ["Rate_USD", "rate_usd", "rate", "Blended_Rate_USD", "blended_rate_usd"]:
        if key in item and item[key] not in (None, ""):
            try:
                return float(item[key])
            except (TypeError, ValueError):
                continue
    return 0.0

Where you currently do something like:

This fixes the “lowercase rate_usd becomes zero” issue and keeps old scenarios working.

4. Allow direct monthly price setting (don’t overwrite manual values)

Right now, apply_cadence_to_item always does:

total_price = cadence_price * units
monthly_price = total_price / total_months


which nukes any manual monthly_price a PM typed in.

4.1. Decide precedence rules

A simple, predictable rule-set:

If monthly_price changed (and > 0) → treat monthly_price as canonical.

Else if cadence_price changed → treat cadence_price as canonical.

Else → keep existing totals.

4.2. Implement inside apply_cadence_to_item

Inside apply_cadence_to_item(new_item, old_item):

changed_cadence = cadence_changed(old_item, new_item)
changed_monthly_price = monthly_price_changed(old_item, new_item)

# 1) compute cadence + units + total_months as you do now
#    (optionally: if not changed_cadence and old_item has retainer.months, reuse it)

# Priority 1: manual monthly price override (only for retainers with months > 0)
if is_retainer and total_months > 0 and changed_monthly_price:
    try:
        monthly_price = float(new_item.get("monthly_price") or 0)
    except (TypeError, ValueError):
        monthly_price = 0

    if monthly_price > 0:
        total_price = monthly_price * total_months
        cadence_price = total_price / units if units > 0 else total_price
        new_item["monthly_price"] = round(monthly_price, 2)
        new_item["cadence_price"] = round(cadence_price, 2)
    else:
        # fall back to cadence logic below
        changed_monthly_price = False

# Priority 2: cadence price is canonical
if not changed_monthly_price:
    # existing logic: derive total from cadence_price (+ legacy fallback)
    ...
    total_price = cadence_price * units
    monthly_price = total_price / total_months if is_retainer and total_months > 0 else 0
    new_item["monthly_price"] = round(monthly_price, 2)

# Write canonical totals
new_item["price_usd"] = round(total_price, 2)
new_item["Price_USD"] = new_item["price_usd"]
new_item["total_price"] = new_item["price_usd"]


This way:

If a PM types $5,000/mo for a 12-month monthly retainer:

Total becomes 60,000

cadence_price becomes 5,000

If they instead change the cadence price (cadence_price), monthly is recomputed.
