Project brief (for Architect + Agent)

Goal
Ship an exec-friendly, ultra-scannable Step-2 screen that summarizes an RFP scope as module cards with expand/collapse and an optional Details drawer. Primary users: Project Managers, Program Managers, C-Level.

Inputs

Word doc (source scope): /mnt/data/SB - L2 to L3 corrected, gantt correct.docx

Screenshot reference (visual copy cues): /mnt/data/7076544e-3617-4b2e-8437-1c372070b92b.png

Non-goals

No full Gantt editor (just a mini bar visualization).

No pricing engine (show effort signals, not full rate math).

Data model (TypeScript)

export type EffortSize = "S" | "M" | "L";

export interface Deliverable {
  id: string;
  label: string;            // chip label (e.g., "Positioning", "Masterbrand system")
  acceptanceCriteria?: string[];
}

export interface DependencyRef { id: string; type: "needs" | "feeds"; }

export interface RoleEffort { role: string; hours?: number; seniority?: "Jr"|"Mid"|"Sr"; }

export interface Module {
  id: string;
  title: string;            // e.g., "Brand Strategy"
  valueStatement: string;   // one-liner for execs
  effort?: { size?: EffortSize; hoursMin?: number; hoursMax?: number };
  outputs: Deliverable[];
  activities: string[];     // 3–6 bullets, verbs first
  risks?: string[];         // max 3
  assumptions?: string[];   // max 3
  dependencies?: DependencyRef[];
  roles?: RoleEffort[];
  channels?: string[];      // e.g., ["Digital"]
  phase?: "Discovery"|"Concept"|"Review"|"Production";
}

export interface ScopeSummary {
  title: string;            // e.g., "RFP Scope for St. Regis Nashville"
  totalPlannedHours?: number; // 4012
  markets?: string[];       // ["US"]
  channels?: string[];      // ["Digital"]
  complexity?: "Low"|"Medium"|"High";
  modules: Module[];
}


Global state

{
  scope: ScopeSummary
  filters: { phase?: string[]; effort?: EffortSize[]; risk?: ("hasRisk"|"noRisk")[]; dept?: string[] }
  expandedModuleIds: Set<string>
  selectedModuleIds: Set<string>     // feeds StickySummaryBar
  ui: { drawerModuleId?: string; loading: boolean }
}

2) Parsing strategy (Architect + Agent)

Objective: Convert the Word doc bullets into ScopeSummary + Module[].

Steps

Load /mnt/data/SB - L2 to L3 corrected, gantt correct.docx via mammoth → HTML/MD string.

Heuristics:

Section headers become Module.title (match known modules from screenshot: “Brand Strategy”, “Brand Identity”, “Brand Architecture & Naming”, “Experiential Activation”, “Campaign Creative”, “Content Production (Video/Audio/Stills)”, “Marketing Collateral & Sales Tools”, “Program Management & Timeline”).

Sentences starting with strong verbs → activities.

Nouns after “Produce/Design/Develop/Deliver” → outputs chips.

If “pre-sales, dependencies, buyer decisioning, timeline” appear, map to dependencies or phase.

If numeric hour hints exist, map to effort.hoursMin/Max; otherwise infer effort.size (S<=120, M<=400, L>400).

Extract globals: title, channels (“Digital”), markets (“US”), complexity (“Medium”), planned hours (“4012”).

Return ScopeSummary.

Keep the parser pure and unit-tested; expose parseDocx(filePath: string): Promise<ScopeSummary>.

3) UI spec (Agent)
HeaderSummary (always visible)

Left: Title, small subline chips for Channels, Markets, Complexity.

Middle: Total planned hours with info tooltip (“how computed”).

Right: Actions: Expand all, Collapse all, Export summary (PDF), Share.

Height target: ≤72px.

ModuleGrid

Responsive: 3-col ≥1280px, 2-col 1024–1279px, 1-col <1024px.

Each ModuleCard shows:

Title

One-line valueStatement

Effort pill (S/M/L or “~X–Yh” if hours present)

Chips: top 3 outputs (ellipsis chip “+N” opens drawer)

Dependency badge count; Risk badge count

Buttons: See details, Select (toggle)

Interactions

Hover chip = tooltip (one-liner)

Click card title or “See details” → DetailsDrawer(moduleId)

Shift+click on card toggles Select

“+N” chips opens the drawer on Deliverables tab

DetailsDrawer (right panel, 420–480px)

Tabs: Overview | Deliverables | Resourcing | Timeline | Dependencies | Notes

Overview: valueStatement, grouped activities, assumptions, risks

Deliverables: list with optional acceptance criteria

Resourcing: roles in a compact table (Role / Seniority / Hours if any)

Timeline: MiniTimeline spark bars across phases (no drag)

Dependencies: upstream/downstream lists; clicking highlights related cards in grid

Notes: free text (read-only placeholder; we’re not editing here)

FilterBar (top of grid)

Filters: Phase, Effort, Risk, Department (optional)

“Clear all” link

Results count updates live

StickySummaryBar (bottom)

Shows X modules selected | Total est. hours (sum of selected if available, else n/a)

Actions: Export Selected, Copy Summary (copies titles + key outputs)

MiniTimeline

Horizontal tiny bars (Discovery/Concept/Review/Production)

Uses phase or inferred default mapping per module

Tooltip on hover: phase name

5) Acceptance criteria (Architect owns; Agent implements)

Readability & IA

Above-the-fold shows: Title, Channels, Markets, Complexity, Total hours.

8–9 module cards visible on laptop without scrolling (collapsed).

Interactions

Expand/Collapse all works and is performant (<16ms per toggle on 30 modules).

Drawer opens within 200ms and is keyboard accessible.

Filters are combinable; clear all resets grid.

Parsing

Loading the .docx populates at least: titles, activities (≥3 each), outputs (≥3 each), and global chips.

If hours are discovered, they appear in effort; otherwise S/M/L is inferred and consistent.

A11y

Tab order logical; focus returns to trigger on drawer close.

All buttons have accessible names; contrast ≥ WCAG AA.

Performance

Lighthouse perf ≥ 90 on desktop.

Initial bundle ≤ 250KB gzipped (excluding Tailwind runtime).

Testing

Unit tests: parser, store selectors, ModuleCard render, Filters behavior.

E2E happy path: load seed → filter → open drawer → export summary.

Deliverables

Repo link, instructions to run (pnpm i && pnpm dev), test report, and a 60s loom walkthrough.

7) Visual guidelines (quick)

Titles 18–20px; body 14–16px; line-height 1.5.

Neutral background; single accent for CTAs/status.

Icons only for status (risk, dependency, effort).

Chips are 28–32px height, truncate to one line.

Keep cards ~280–320px tall collapsed, with max 5 visible elements.
