Fixes to implement in v2.8 (ready‑to‑paste changes)

Below are surgical patches the Replit agent can apply in your FastAPI exporter. They don’t change pricing/timeline math—just how the MSPDI XML is written.

A. Build a proper WBS tree and set summary flags correctly

What to do

When you assemble tasks, first build a tree (by WBS / Parent_WBS).

For any node that has children → write <Summary>1</Summary>, set <Work>PT0M</Work> on that row, and do not attach assignments to it.

Only leaf rows (no children) should have <Summary>0</Summary> and carry work/assignments.

Why
MSP/Workfront assume parents are roll‑ups. Assigning work to a parent or calling a parent Summary=0 makes importers choke.

Patch sketch (insert inside your XML‑building function before emitting <Task>):

# Build parent → children map from WBS
children = defaultdict(list)
for row in rows:
    parent_wbs = row.get("Parent_WBS_ID") or ""
    children[parent_wbs].append(row)

def is_summary(row):
    return any(ch.get("Parent_WBS_ID") == row["WBS_ID"] for ch in rows)

# When writing each <Task>:
summary = 1 if is_summary(row) else 0
SubElement(task_el, "Summary").text = str(summary)
if summary == 1:
    SubElement(task_el, "Work").text = "PT0M"   # no direct work on parents
    # (optional) omit Start/Finish for parents; importer will roll up

B. Stop pinning every task to SNET on the same day

What to do

For leaf tasks: write <ConstraintType>0</ConstraintType> (ASAP) and omit <ConstraintDate>.

Use SNET/FNET only where business rules require it (milestones, client dates, etc.).

if is_leaf(row):
    SubElement(task, "ConstraintType").text = "0"  # ASAP
else:
    SubElement(task, "ConstraintType").text = "0"  # parents ASAP as well
# do NOT write <ConstraintDate> unless needed

C. Make dates consistent with duration (or omit dates and let the tool schedule)

Pick one approach; both work.

Option 1 — Let Workfront/MSP schedule:
For leaf tasks, write Duration and predecessor links; omit hard Start and Finish. (Keep Project/StartDate and maybe the phase anchors.) This is safest and most “MSP‑correct”.

Option 2 — Keep dates:
If you must keep dates, ensure Finish = Start + Duration under MinutesPerDay = 480. Example:

start = project_start + datetime.timedelta(days=row["Start_Offset_Days"])
mins  = int(row["Duration_Days"] * 480)
finish = start + datetime.timedelta(minutes=mins)

SubElement(task, "Start").text = start.strftime("%Y-%m-%dT%H:%M:%S")
SubElement(task, "Finish").text = finish.strftime("%Y-%m-%dT%H:%M:%S")
SubElement(task, "Duration").text = f"PT{mins}M"


Critical: never write Start/Finish for a 1‑day window with a 6‑day Duration (that’s the contradiction seen in e.g. ADA Compliance).

D. Round durations to whole days (optional but cleans up “hours” displays)

If you want “days” to show everywhere, round to whole days before writing Duration:

mins = int(round(row["Planned_Hours"] / 8.0) * 480)  # 8h/day
SubElement(task, "Duration").text = f"PT{mins}M"


Keep a toggle (“Round durations to whole days”) so producers can disable rounding when needed.

E. Name the project explicitly

Write the real project name from Step‑1 or the uploaded filename:

proj_name = user_inputs.get("project_name") or (LAST_UPLOAD_FILENAME or "Scenario A").rsplit(".",1)[0]
SubElement(project_el, "Name").text = proj_name
# (optional) also:
SubElement(project_el, "Title").text = proj_name


Your current XML sets <Name>Project from Scenario A</Name>, which is why Workfront shows that label.
