A) Make DB v3 the primary database (keep v4 as overlay/fallback)

What’s there now:
The loader prefers v4 (v4b → v4 → CSVs). It then optionally loads v3 (Drivers + All_Task_Rows) mainly to enrich “Service Department”. You can see the v4‑first order and the v3 locator helper in AgencyDB.load() and _find_v3_path().

Goal: Flip the order so v3 can be primary with v4 used as a selective overlay (only for sheets missing in v3).

A.1 Loader flag + environment variable

Add a feature flag: APB_PRIMARY_DB_VERSION (default v4, set to v3 to switch).

Keep the existing APB_V3_DB path secret (the loader already checks it).

Patch (server — where AgencyDB is defined):

# at top, near other env helpers
PRIMARY = os.getenv("APB_PRIMARY_DB_VERSION", "v4").lower()  # 'v3' or 'v4'

def _find_v4_path() -> str | None:
    for p in [
        "Replit_App_DB_READABLE_FullRows_v4b.xlsx",
        "Replit_App_DB_READABLE_FullRows_v4.xlsx",
        "Replit_App_DB_READABLE_FullRows_v4_csvs",  # dir
    ]:
        if os.path.exists(p):
            return p
    return None

class AgencyDB:
    # ...

    def load(self):
        prefer_v3 = (PRIMARY == "v3")

        v3_path = _find_v3_path()
        v4_path = _find_v4_path()

        if prefer_v3 and v3_path:
            self._load_from_v3_primary(v3_path, v4_path)  # v3 base, v4 overlay

            self._load_from_v4_primary(v4_path, v3_path)  # current behavior

B) Fix rate/pricing mismatches between app and Workfront

Observed problem: XML exports do not include resource rates or assignment costs, so Workfront falls back to its own system rates—hence totals differ from what you set in Step 3. In your current XML files, <Resources> have names but no <StandardRate> or cost tables; assignments don’t include <Cost>. Examples:

Only “Unassigned” resource and no rate/cost in one export.

Another export has many resources but still no <StandardRate> entries.

Fix: Write the rates and costs into MSPDI:

When pricing mode = Flat_Blended:

Put one resource (“Unassigned” or “Blended Team”) with <StandardRate> = the blended rate from Step 3 (e.g., 195).

Assign all work to this resource.

For each assignment, set <Cost> = (Work minutes / 60) * rate.

When pricing mode = Per_Resource:

Create one resource per role (Account Manager, Strategist, Designer, etc.).

For each, write <StandardRate> using Rate Band & Role lookup (Role_Rate_Card/Matrix from DB).

On every assignment, compute and set <Cost> again from the role‑specific rate.

Patch (exporter — where MSPDI XML is built):

# helpers
def _std_rate_for(role: str, mode: str, band: str, blended: float, db: AgencyDB) -> float:
    if mode == "Flat_Blended" and blended:
        return float(blended)
    # per-resource lookup
    try:
        # prefer matrix; fallback to role_rate_card
        m = db.rate_matrix
        if m is not None:
            row = m[(m["Role"].str.strip().str.lower()==role.strip().lower()) &
                    (m["Band"].str.strip().str.lower()==band.strip().lower())]
            if not row.empty:
                return float(row["USD_per_hour"].iloc[0])
        rc = db.role_rate_card
        if rc is not None:
            row = rc[rc["Role"].str.strip().str.lower()==role.strip().lower()]
            if not row.empty:
                return float(row[band].iloc[0])  # columns like Standard_US, Premium_US
    except Exception:
        pass
    return float(blended or 0)

# when writing <Resources>
for res in resources_list:  # e.g., [{'uid':1,'name':'Designer','role':'Designer'}]

    SubElement(r, "ID").text  = str(res["uid"])

    SubElement(r, "Type").text = "1"
    rate = _std_rate_for(res["role"], pricing_mode, rate_band, blended_rate, db)
    SubElement(r, "StandardRate").text = f"{rate:.2f}"

Result: Workfront will ingest both rates and costs aligning with your Step‑3 pricing—so totals stop drifting after import. (Your current XMLs lack these fields, which is why Workfront “re‑prices” them.)

C) Scenario Builder — make A / B / C materially different

Observed: A, B, C often look the same because they’re all built from the same base hours column and similar component sets.

What to change:

Use distinct scenario multipliers (hours + overhead) and component sets:

Add a small config table (or reuse Scenario_Templates if present) with per‑scenario knobs:

SCENARIO_MULT = {
  "A": {"hours_mult": 1.00, "qa_pct": 0.00, "pm_pct": 0.05, "strip_optional": True},
  "B": {"hours_mult": 1.15, "qa_pct": 0.03, "pm_pct": 0.10, "strip_optional": False},
  "C": {"hours_mult": 1.30, "qa_pct": 0.05, "pm_pct": 0.12, "include_addons": True}
}


In the builder, after selecting base hours via the column
f"{complexity}__{tier}_Hours" (that’s how your loader selects hours now), multiply by the scenario knobs.

A (lean): remove “optional/nice‑to‑have” components (mark via tag or a list).
B (producer‑edited): keep all core components and add PM/QA overhead.
C (upsell): include add‑ons and increase hours slightly.

Make the pricing genuinely diverge:

Compute scenario_price = sum(hours_by_role * rate_by_role) using the same rate band, then apply scenario‑specific management overheads as separate “Tasks” (PM, QA) so the difference is visible both in Step 3 and in the XML (and not just hidden in numbers).

Patch (server — in the function that constructs scenarios A/B and in /api/build_scenario_c):

def _apply_scenario_knobs(items, letter, complexity, tier, pricing_mode, rate_band, db, blended_rate=None):
    knobs = SCENARIO_MULT[letter]
    for it in items:
        base_col = db._scenario_col(complexity, tier)   # e.g. Advanced__T2_MediumVolume_Hours
        for r in it["hours_by_role"]:
            r["hours"] = r["hours"] * knobs["hours_mult"]
        # strip/augment components
        if knobs.get("strip_optional"):
            it["components"] = [c for c in it["components"] if not c.get("optional")]
        if knobs.get("include_addons"):
            it["components"].extend(it.get("addons", []))
    # add PM/QA overhead as explicit task groups
    pm_hours = sum(sum(r["hours"] for r in it["hours_by_role"]) for it in items) * knobs["pm_pct"]
    qa_hours = sum(sum(r["hours"] for r in it["hours_by_role"]) for it in items) * knobs["qa_pct"]
    if pm_hours > 0:
        items.append(_make_overhead_item("Project Management", pm_hours))
    if qa_hours > 0:
        items.append(_make_overhead_item("QA / Reporting", qa_hours))
    return items


Bind this in both A/B builder route and the Scenario C route so all three letters branch differently.

D) Complexity & Volume multipliers that produce realistic estimates

What’s there now: Hours come from a per‑row column like Advanced__T2_MediumVolume_Hours. (That mapping already exists in the loader as _scenario_col.)

What to add:

Read “global” multipliers from Pricing_Settings or Timeline_Scaling if present (e.g., Complexity.Advanced = 1.25, Volume.T3_HighVolume = 1.20). Those sheets are already loaded by AgencyDB.

Apply them on top of the column hours, so we have:

final_hours = db_hours_column
              * complexity_multiplier
              * volume_multiplier
              * scenario_hours_multiplier (A/B/C)


Cap and floor multipliers (e.g., min 0.5x, max 2.0x) to avoid extremes from AI suggestions.

Patch (where hours are computed):

def _resolve_global_multipliers(db: AgencyDB, complexity: str, tier: str) -> tuple[float,float]:
    cm = 1.0; vm = 1.0
    try:
        ps = db.pricing_settings
        if ps is not None:
            cm_row = ps[ps["Key"].str.lower()==f"complexity.{complexity.lower()}"]
            vm_row = ps[ps["Key"].str.lower()==f"volume.{tier.lower()}"]
            if not cm_row.empty: cm = float(cm_row["Value"].iloc[0])
            if not vm_row.empty: vm = float(vm_row["Value"].iloc[0])
    except Exception:
        pass
    return cm, vm

def _apply_multipliers(row_hours, complexity, tier, letter, db):
    cm, vm = _resolve_global_multipliers(db, complexity, tier)
    sm = SCENARIO_MULT[letter]["hours_mult"]
    return max(0.5, min(2.0, row_hours * cm * vm * sm))


Wire _apply_multipliers wherever we loop rows to compute scenario hours.

Outcome:

Scenario A, B, C numerically differ.

Differences are traceable (PM/QA tasks present).

Changing complexity/tier actually moves totals (A/B now produce realistic spreads).

Notes / gotchas

Workfront import behavior: If Workfront still doesn’t honor costs, add <FixedCost> on each leaf <Task> (in addition to <Assignment><Cost>). Some Workfront tenants map either assignment cost or fixed task cost on import—our patch can set both.

Rate Band mapping: Ensure your DB’s Role_Rate_Card headers match the UI band keys exactly (e.g., Standard_US, Premium_US). If they differ, add a small alias map.

Service Department column: Your CSV/XLS “Workfront” export column set already includes a “Service Department” field; keeping v3 primary preserves those values (v4 is overlaid only where v3 lacks a sheet).
