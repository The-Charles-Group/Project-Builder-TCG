1) “Lack of dependencies in subtasks to reduce the duration?”
Symptom

In Workfront, only the first instance of a repeated sub‑task gets a predecessor. All subsequent instances in that component start at project start, so whole task groups run in parallel (you saw this in Strategy → edit’s children).

Root cause

When we expand repeated rows (e.g., multiple role lines or repeated L3 pieces under a component), we only attach one PredecessorLink. The chain isn’t built across all instances.

Fix (server)

Add a deterministic chaining step after we’ve expanded the rows for a deliverable/component:

# server/timeline.py (new helper)
def chain_instances(instances: list[TaskNode]) -> None:
    """Give every instance a FS predecessor to the previous instance."""
    for i in range(1, len(instances)):
        prev = instances[i-1]
        curr = instances[i]
        curr.predecessors.append(Predecessor(uid=prev.uid, type="FS", lag=0))


Then apply it inside the deliverable assembly:

# after we group rows by (deliverable -> component -> L2 task group)
for group in l2_groups:  # e.g., ["deck_build", "internal_review", "client_review", ...]
    instances = expand_rows_for_group(group)  # returns list[TaskNode] in desired order
    chain_instances(instances)                # <--- NEW
    stitched.extend(instances)


Finally, chain groups to each other (waterfall) using the same helper on the last‑UID of each group.

Fix (XML writer)

Ensure every TaskNode.predecessors becomes one or more <PredecessorLink> blocks:

# server/xml_writer.py
for pred in node.predecessors:
    pl = SubElement(task, "PredecessorLink")
    SubElement(pl, "PredecessorUID").text = str(pred.uid)
    SubElement(pl, "Type").text = "1"         # Finish-to-Start
    SubElement(pl, "LinkLag").text = "0"
    SubElement(pl, "LagFormat").text = "7"    # days


Acceptance test

Build A/B/C, export XML, import to Workfront, switch to a view with “Predecessors” and “Successors” columns. All repeated L3 rows under the same L2 should chain serially (FS) and groups should also chain serially. Duration should collapse (no unintended parallelism).

5) “Timeline shows weekends; should be 9–5 and respect holidays”
What’s already correct in XML

Exports set 480 minutes per day and Monday–Friday workdays under <Calendar>. (Saturday/Sunday are non‑working.)

What’s wrong

Step 4’s math adds calendar days, not business days, and doesn’t consult a holiday list—so UI dates differ from Workfront/MSP after import.

Fix (server date engine used by UI & XML)

Add business‑time helpers and use them everywhere we compute Start/Finish:

BUSINESS_START = datetime.time(9, 0)
BUSINESS_END   = datetime.time(17, 0)
WORK_MIN_PER_DAY = 480

def is_business_day(d: date, holidays: set[date]) -> bool:
    return d.weekday() < 5 and d not in holidays  # Mon=0..Fri=4

def add_business_days(start: date, days: int, holidays: set[date]) -> date:
    d = start
    step = 1 if days >= 0 else -1
    remaining = abs(days)
    while remaining:
        d += timedelta(days=step)
        if is_business_day(d, holidays):
            remaining -= 1
    return d

def calc_finish(start_dt: datetime, duration_days: int, holidays: set[date]) -> datetime:
    start_date = start_dt.date()
    end_date = add_business_days(start_date, duration_days, holidays)
    return datetime.datetime.combine(end_date, BUSINESS_END, start_dt.tzinfo)


Add a Holidays source: read from Timeline_Params or a new Holidays sheet. If absent, allow a comma‑separated holiday field in Step 3. (XML still writes the Standard calendar, but UI and assignment math now align with business days.)

Acceptance test
