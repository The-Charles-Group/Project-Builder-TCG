Quick, safe fixes to the v2.8 exporter

Below are minimal surgical changes that stop the import errors and keep the rest of your pipeline intact. They match your current exporter in v2.8 prod.docx (the convert_excel_to_mspdi section). I’m showing only the lines to edit/add.

1) Write ASAP constraints by default (only date‑pin when needed)
# when writing each <Task> ...
is_summary = bool(r.get("IsSummary", False))
SubElement(task, "Summary").text = "1" if is_summary else "0"

# Constraints: default to ASAP for non-summary tasks
if not is_summary:
    SubElement(task, "ConstraintType").text = "0"  # ASAP
else:
    # summaries may omit constraint or leave default
    SubElement(task, "ConstraintType").text = "0"


(Your 03:38 file shows SNET (4) everywhere; switch to ASAP (0) unless the UI explicitly asked to pin a date.) Examples of the current SNET pattern are visible here.

2) Don’t hard‑code Start/Finish on leaf tasks (let Workfront compute)
# Only write Start/Finish on the top-level project and *optional* summaries.
# For normal tasks, write Duration and the PredecessorLink(s); let the engine schedule dates.
if is_summary:
    SubElement(task, "Start").text  = uid_to_sched[r["UID"]]["Start"]
    SubElement(task, "Finish").text = uid_to_sched[r["UID"]]["Finish"]
# ... but for leaf tasks, SKIP setting Start/Finish entirely


This removes the contradiction “finish tomorrow with a 3‑week duration” that we see in several tasks.

If you must include dates, compute Finish = Start + Duration (working time) so they are consistent with MinutesPerDay=480 and your calendar.

3) Mark true parents as summaries and avoid assignments on them

Ensure you set Summary=1 for rows that have children and don’t put Work/assignments on those rows; keep work only on leaves. (You’re already generating Summary in the exporter loop—just make sure your rows include a reliable IsSummary flag and you honor it when writing tasks.) The consequences of not doing this are present in the XML you uploaded.

4) Make durations calendar‑clean (optional but improves display)

If you want Workfront to show durations as “days” instead of “hours”, round leaf durations to whole multiples of 480 minutes when possible:

dur_min = int(round(hours_for_task * 60))
dur_min = int(round(dur_min / 480.0)) * 480  # snap to whole days
SubElement(task, "Duration").text = f"PT{dur_min}M"


Your file contains many fractional‑day durations that force an hours display. Examples: 7,200m vs 5 working days, etc.

5) Pass through the real project name

Replace the line that forces “Project from {sheet_name}” and use the actual project name the UI already has.
Change:

# BEFORE
SubElement(project, "Name").text = f"Project from {sheet_name}"
# AFTER
SubElement(project, "Name").text = project_name  # use payload.project_name / Step 1 title
