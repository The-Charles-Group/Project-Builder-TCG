1) Gantt (Step‑4) freezes when a user stretches dates
Root cause (server + client interaction)

The Gantt UI is calling write endpoints per pixel/drag event, especially /api/timeline/update_task and/or /api/scenario/sync, and the server does not throttle or coalesce these writes. That makes the browser and server fight through dozens of in‑flight updates during a drag, causing the freeze. The sync endpoint stores full scenario snapshots with version/csum—but there’s no per‑session write‑rate guard today.

In parallel, your SSE timeline generator (/api/ai/generate_timeline) is heavy. If any client watcher triggers it during edits, load spikes (I see chunking/progress code—good—but avoid calling this while dragging).

Permanent fix (safe, minimal changes)

A. Server: throttle + batch writes

Add a write‑throttle to /api/scenario/sync so we ignore updates arriving too fast (e.g., <150 ms apart) per session:

Keep last_write_ms in SCENARIO_SYNC_STATE[session_id], return a “throttled/no‑op” response if a new write comes too soon. (Drop on server; the client keeps animating locally.)

Make /api/timeline/update_task idempotent and light:

Update only the matching WBS row and avoid recalculating the entire scenario on every drag tick. Recompute totals for that deliverable only (the method _recompute_totals is already in memory).

Add a tiny batch endpoint /api/timeline/update_tasks_batch (same logic as update_task, but array‑based) so the client commits one payload on mouseup.

Drop‑in patch (server):
Add the throttle & batch handling to your existing file.

# --- Add near SCENARIO_SYNC_STATE definition ---
WRITE_THROTTLE_MS = 150  # block writes faster than this per session

# In /api/scenario/sync (after you load server_state):
now_ms = int(time.time() * 1000)
last_ms = int(server_state.get("last_write_ms", 0))
if now_ms - last_ms < WRITE_THROTTLE_MS:
    # Too soon; tell client nothing changed (prevents freeze during drag)
    return {
        "serverVersion": server_state["version"],
        "hasChanges": False,
        "hasConflicts": False,
        "conflicts": [],
        "timestamp": now_ms,
        "throttled": True
    }
server_state["last_write_ms"] = now_ms

B. Client: commit on pointerup, not per mousemove

In the Gantt component, change the event wiring:

While dragging → local bar stretch only.

On pointerup (drop) → send one POST /api/timeline/update_tasks_batch with the final dates.

Add a debounce(300ms) for any autosave path that still uses /api/scenario/sync.

This immediately stops the stutter/freeze and scales well.
