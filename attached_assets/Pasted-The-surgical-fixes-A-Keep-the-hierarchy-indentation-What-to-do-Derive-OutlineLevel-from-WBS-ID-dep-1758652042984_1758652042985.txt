Use the app’s waterfall to compute each deliverable’s Start/Finish and then anchor children under their parent window. We’ll keep “days” by converting to minutes using the app’s calendar (MinutesPerDay=480).

Where to change

In the server (v2.6), Step 4 already has:

Business‑day helpers and a compute_waterfall_schedule() that rounds up durations and increments by Mon–Fri.

STEP4_SCHEDULE to persist the last schedule per scenario.

Use that map during export: when creating each task, look up its deliverable code and use that start/end instead of the static project start. Set ConstraintType=StartNoEarlierThan (4) and ConstraintDate to the computed start to stop Workfront from drifting earlier.

Convert Duration_Days → minutes:

Apply the business‑day deliverable window:

win = STEP4_SCHEDULE.get(current_scenario, {}).get("map", {}).get(deliverable_code)

if win:

D. Put predecessors back (and normalize summary links)

What to do
For each task with a Dependencies value (WBS IDs separated by comma/semicolon), add <PredecessorLink> with Type 1 (Finish‑to‑Start). If a dependency points to a summary, re‑wire it to the last leaf beneath that summary; likewise if the successor is a summary, re‑wire to the first leaf under it. This matches your documented behavior.

Where to change
In the exporter after you’ve built wbs → uid and parent → [children] maps:

def last_leaf_under(wbs):
    cur = wbs
    while cur in children_by_parent and children_by_parent[cur]:
        cur = children_by_parent[cur][-1]  # last child in order
    return cur

def first_leaf_under(wbs):
    cur = wbs
    while cur in children_by_parent and children_by_parent[cur]:
        cur = children_by_parent[cur][0]   # first child in order
    return cur

for row in df.itertuples():
