3. Backend behavior to enforce
3.1 Green “Build Scenario”

Endpoint: /api/pricing/build_scenario

Behavior:

If reset=True → always rebuild from Step 2 baseline.

If reset=False and no scenario exists → build from Step 2 baseline.

If reset=False and a scenario already exists → just return SCENARIO_STORE[session_id]["scenario"] (do not overwrite Step 3 edits).

Pseudo:

def build_scenario(session_id: str, reset: bool = False):
    if not reset and session_id in SCENARIO_STORE:
        return SCENARIO_STORE[session_id]["scenario"]

    scenario = build_scenario_from_step2_baseline(session_id)
    SCENARIO_STORE[session_id] = {"scenario": scenario}
    return scenario

3.2 Project Scenario edits

When user edits Hours / Rate / Cadence and hits Save:

Update SCENARIO_STORE[session_id]["scenario"] for that deliverable.

Call _recompute_totals() on the scenario.

Return updated scenario totals so the UI can refresh the summary cards.

No Step 2 / build_scenario calls here.

3.3 Blue “Re-build Scenario”

New (or existing) endpoint: /api/pricing/rebuild_breakdown

Behavior:

Read scenario = SCENARIO_STORE[session_id]["scenario"]

Call _recompute_totals(scenario)

Rebuild:

Deliverable Pricing Details table

One-time / Retainer summary cards

Do not touch Step 2 or change Hours/Rate/Price in the scenario itself.

So Re-build is “refresh views from current data”, not “start over”.

3.4 Reset from Step 2

Endpoint: same as build_scenario with reset=True.

After reset, Project Scenario + Deliverable Pricing Details + summary should all reflect freshly computed baseline values.
