Below is a drop‑in blueprint that works with your current v2.7 backend and UI. I kept it minimal so you can wire it quickly, but it’s complete enough for Replit’s Agent to implement without guesswork.

What’s already in v2.7 that we can reuse

The full deliverable list is already exposed by /api/options (deliverables: [{ Deliverable_Code, Deliverable, Category }]). Use this for the Step‑2 picker/search.

Build still takes selected_deliverable_codes and returns Scenarios A/B; it also stores them in _CURRENT_SCENARIOS for later steps (timeline & exports).

Canonicalization helper exists to map a free‑text label to a DB deliverable code (_canonical_deliverable_code). We’ll expose a tiny endpoint around it for type‑ahead/“paste to add”.

Reconcile continues to work as the “AI hints” panel (middle column). We’ll keep using it, but users will no longer be blocked by it.

Backend: two small endpoints (optional but very useful)

If you want zero backend changes, you can skip this and search on the client using /api/options. If you want a cleaner UX (server‑side search + paste‑to‑add), add these two.

1) Search deliverables (server‑side filter/type‑ahead)

# --- Add near your other GET routes ---
@app.get("/api/search_deliverables")
def api_search_deliverables(q: str = "", limit: int = 50):
    if not DB.loaded: DB.load()
    df = DB.deliverables.copy()
    q = (q or "").strip().lower()
    if q:
        mask = (
            df["Deliverable"].astype(str).str.lower().str.contains(q)
            | df["Category"].astype(str).str.lower().str.contains(q)
            | df["Deliverable_Code"].astype(str).str.lower().str.contains(q)
        )
        df = df[mask]
    rows = df[["Deliverable_Code", "Deliverable", "Category"]].head(limit).to_dict("records")
    return {"items": rows}


2) Resolve free‑text to a deliverable code (lets users paste labels)

from pydantic import BaseModel
class ResolveDeliverablesPayload(BaseModel):
    inputs: list[str] = []

@app.post("/api/resolve_deliverables")
def api_resolve_deliverables(p: ResolveDeliverablesPayload):
    if not DB.loaded: DB.load()
    out = []
    for s in (p.inputs or []):
        code = _canonical_deliverable_code(s)   # v2.7 helper
        row = DB.deliverables[DB.deliverables["Deliverable_Code"].astype(str)==str(code)]
        if row.empty: 
            continue
        out.append({
            "input": s,
            "code": code,
            "deliverable": str(row["Deliverable"].iloc[0]),
            "category":  str(row["Category"].iloc[0]),
        })
    return {"resolved": out}


_canonical_deliverable_code is already in v2.7; we’re just exposing it via HTTP.

Frontend (Step 2) — minimal, robust state model

Add three arrays to Step‑2 component state:

const [selectedCodes, setSelectedCodes] = useState<string[]>(initialSelectedFromStep1);
const [removedCodes,  setRemovedCodes]  = useState<string[]>([]);          // “soft delete”
const [addedCodes,    setAddedCodes]    = useState<string[]>([]);          // explicit user adds


selectedCodes
The authoritative list you will pass to /api/build.

removedCodes
Soft‑deleted items (show in a “Removed” bucket with an Undo). Do not include these when calling /api/reconcile or /api/build.

addedCodes
Track what the user explicitly added (optional, for UX badges/telemetry).

UI behaviors

Left panel “Your selection”
Render chips/rows for selectedCodes. Each row gets a persistent Remove (X).

function onRemove(code: string) {
  setSelectedCodes(prev => prev.filter(c => c !== code));
  setRemovedCodes(prev => prev.includes(code) ? prev : [...prev, code]);
}


Left panel “Removed” (soft delete bucket)
Show removedCodes with Restore control.

function onRestore(code: string) {
  setRemovedCodes(prev => prev.filter(c => c !== code));
  setSelectedCodes(prev => prev.includes(code) ? prev : [...prev, code]);
}


Add any deliverable

Option A (no backend change): client‑side search over /api/options.deliverables.

Option B (nicer): query /api/search_deliverables?q=… and/or /api/resolve_deliverables.
When adding:

function onAdd(code: string) {
  setRemovedCodes(prev => prev.filter(c => c !== code)); // un-soft-delete if needed
  setSelectedCodes(prev => prev.includes(code) ? prev : [...prev, code]);
  setAddedCodes(prev => prev.includes(code) ? prev : [...prev, code]);
}


Reconcile (middle column)
Call /api/reconcile with only the current selectedCodes; do not include removedCodes.
This keeps AI “ADD/DELETE” suggestions accurate without re‑introducing things the user just removed.
