2. Things to be careful about

Two spots where it’s easy for someone to accidentally undo the fix:

A. What collectScenarioFromUi() should and should not do

Good:

Update scenario‑level metadata on SCENARIO_A, like:

project_start

pricing_mode

complexity

volume_tier

maybe blended_rate_usd, etc.

Leave the items list intact (deliverables, components, hours, cadence, prices).

Bad (don’t do this):

Don’t call the old function that rebuilds items from scratch using the database and baseline (i.e., don’t re‑clone Step 2).

Don’t call set_baseline_and_scenario() from Step 3. That’s only for Step 2 builds and explicit “Reset from Step 2” actions.

If they reuse any old “build scenario from DB” helper in collectScenarioFromUi, you’ll be back to: click Build Scenario → items snap back to baseline.

B. Make sure /api/scenarios + rebuildPricingFromBackend() are the only pricing entry points

The architect’s plan already hints at this:

If /api/scenarios returns no working scenario, then call the build function once as a fallback (for brand‑new sessions).

Otherwise, everything should go through:

/api/scenario/sync

/api/pricing/rebuild_breakdown

Ask them explicitly to:

Remove/disable any old paths that:

compute totals purely on the front‑end, or

call pricing endpoints that don’t go through SCENARIO_STORE.

1) Step 3 initial load

Add initPricingStep() that runs on DOMContentLoaded for Step 3:

async function initPricingStep() {
  const sessionId = window.SESSION_ID;

  // 1. Get existing working scenario (don’t rebuild)
  const resp = await fetch('/api/scenarios', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ session_id: sessionId, reset: false })
  });
  const data = await resp.json();

  // If no scenario exists (new session), fall back to existing Step‑2 buildOnce logic
  if (!data.ok || !data.scenarios || !data.scenarios.A) {
    // OPTIONAL: call the existing buildScenariosAB() once here, then re-call initPricingStep
    console.warn('No working scenario found, need to seed from Step 2 builder.');
    return;
  }

  window.SCENARIO_A = data.scenarios.A;

  // 2. Sync + rebuild both panels + cards from backend
  await window.rebuildPricingFromBackend(window.SCENARIO_A);
}

document.addEventListener('DOMContentLoaded', () => {
  initPricingStep().catch(console.error);
});

2) Make Deliverable Pricing Details write back into SCENARIO_A

For each editable input in “Deliverable Pricing Details”:

let pricingDetailsDirty = false;

function updateScenarioItem(deliverableCode, componentName, updater) {
  if (!window.SCENARIO_A || !Array.isArray(window.SCENARIO_A.items)) return;
  const item = window.SCENARIO_A.items.find(i =>
    String(i.Deliverable_Code) === String(deliverableCode) &&
    String(i.Component) === String(componentName)
  );
  if (!item) return;
  updater(item);
  pricingDetailsDirty = true;
}

function onPricingDetailHoursChange(deliverableCode, componentName, newHoursStr) {
  const hours = parseFloat(newHoursStr) || 0;
  updateScenarioItem(deliverableCode, componentName, (item) => {
    item.Planned_Hours = hours;
    const rate = item.Rate_USD || item.rate_usd || window.DEFAULT_BILLABLE_RATE_USD || 0;
    item.Price_USD = Math.round(hours * rate * 100) / 100;
    item.price_usd = item.Price_USD;
  });
}

function onPricingDetailRateChange(deliverableCode, componentName, newRateStr) {
  const rate = parseFloat(newRateStr) || 0;
  updateScenarioItem(deliverableCode, componentName, (item) => {
    item.Rate_USD = rate;
    const hours = item.Planned_Hours || item.planned_hours || 0;
    item.Price_USD = Math.round(hours * rate * 100) / 100;
    item.price_usd = item.Price_USD;
  });
}


Hook these up to the <input> onchange/onblur events for hours and rate.

async function collectScenarioFromUi(scenario) {
  if (!scenario) return;

  // Example: read project start / pricing mode / rate band from Step 3 header fields
  const projectStart = document.getElementById('project-start-input').value;
  const pricingMode = document.getElementById('pricing-mode-select').value;
  const rateBand     = document.getElementById('rate-band-select').value;

  scenario.project_start = projectStart;
  scenario.pricing_mode  = pricingMode;
  scenario.rate_band     = rateBand;

  // IMPORTANT: Do NOT regenerate scenario.items here.
}

async function onStep3BuildScenarioClick() {
  if (!window.SCENARIO_A) return;
  collectScenarioFromUi(window.SCENARIO_A);
  await window.rebuildPricingFromBackend(window.SCENARIO_A);
}


Wire the rocket button to onStep3BuildScenarioClick().

5) Error handling / edge cases

If /api/scenarios or rebuildPricingFromBackend returns an error, keep the pricingDetailsDirty flag set and show an error message instead of silently dropping changes.

Ensure other flows (hotkeys, autosave, etc.) that affect pricing also call rebuildPricingFromBackend so there’s only one authoritative code path.
