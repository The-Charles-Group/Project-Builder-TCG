GOAL

Make deliverables (L2 tasks) import into Workfront as a tight waterfall:
each deliverable starts as soon as the previous one finishes (no work‑wait‑work‑wait), with weekends handled by Workfront’s calendar.
Components/tasks/roles keep behaving as they do now.

1. Why gaps are happening (so they know what to undo)

In convert_excel_to_mspdi the exporter treats deliverables (OutlineLevel=2) as manually scheduled and gives them a constraint (“SNET / Must Start On”) plus manual-duration format 53, while leaves lower‑level tasks as auto‑scheduled.

The timeline endpoint strips all dependencies before saving the schedule result, so the XML currently has no FS chain between deliverables – Workfront only sees the manual start dates and honors those.

Result: Workfront can’t pull deliverables left even if earlier work finishes; it just obeys those “must start on” dates → work‑wait‑work‑wait.

We want the opposite: deliverables should be ASAP, driven by dependencies, not locked dates.

2. Required behavior (clear spec)

For L2 deliverables only:

ConstraintType = ASAP

Export <ConstraintType>0</ConstraintType> (As Soon As Possible)

Do not export <ConstraintDate> for L2 deliverables.

Not manually scheduled

Do not output ManualStart, ManualFinish, ManualDuration, or any “ManuallyScheduled” flags for L2.

Duration format for deliverables should be the same as auto tasks: 7 (Elapsed Days), not 53.

FS chain between deliverables

After building all <Task> elements, identify all deliverables (OutlineLevel=2, WBS like 1.1, 1.2, …).

Sort them by WBS order.

For each deliverable after the first, add a <PredecessorLink>:

<PredecessorLink>
  <PredecessorUID>[UID of previous L2 deliverable]</PredecessorUID>
  <Type>1</Type>           <!-- 1 = Finish-to-Start -->
  <LinkLag>0</LinkLag>     <!-- no lag -->
  <LagFormat>7</LagFormat> <!-- same as other tasks -->
</PredecessorLink>


This is L2-only. Don’t change the existing L3+ dependencies/behavior.

Milestones are protected

Milestones like “Strategy Approval”, “Creative Approval”, “Launch Complete” keep whatever constraint logic they already have (often Must Start On / fixed date).

Do not attach them into the L2 chain unless that’s already happening.

Weekends

Leave the project calendar logic as‑is. The XML calendar already encodes the working days; Workfront will handle weekends and translate durations to calendar dates.
