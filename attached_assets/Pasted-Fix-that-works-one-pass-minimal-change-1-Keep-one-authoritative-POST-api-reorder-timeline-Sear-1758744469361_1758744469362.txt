1) Keep one authoritative POST /api/reorder_timeline

Search your server file for @app.post("/api/reorder_timeline"). Delete or comment out all but one and replace it with the snippet below. This version:

Computes the sequential schedule (start→end) in the exact order the user saved

Persists it into _CURRENT_SCENARIOS

Sets user_order and manual_order_locked = True so subsequent /api/build calls must respect it

# --- Authoritative: Step‑4 "Save Order" -> sequential schedule + persistence
@app.post("/api/reorder_timeline")
def api_reorder_timeline(p: ReorderPayload):
    if not DB.loaded:
        DB.load()

    letter = (p.scenario_letter or "A").upper()
    scens = _current_scenarios()
    scen = scens.get(letter) or {}

    # choose a base start date (payload > scenario > today)
    base_start = (
        p.project_start
        or scen.get("project_start")
        or datetime.date.today().isoformat()
    )

    # canonicalize codes & included_map (names are allowed on input)
    order_codes = [_canonical_deliverable_code(x) for x in (p.deliverable_codes or [])]
    inc_map = { _canonical_deliverable_code(k): v for k, v in (p.included_map or {}).items() }

    items: list[dict] = []
    cursor_date = None

    # Build a quick lookup of existing items so we keep labels/category/etc.
    prev_by_code = { str(it.get("deliverable_code")): dict(it)
                     for it in (scen.get("items") or []) }

    for code in order_codes:
        # task groups: from client, else derive all present for that deliverable
        included = inc_map.get(code)
        if not included:
            sub = DB.all_rows[DB.all_rows["Deliverable_Code"].astype(str) == str(code)]
            included = sorted(set(sub["task_group"].dropna().astype(str).tolist()))

        start_for_this = base_start if cursor_date is None else str(cursor_date)
        sched = DB.build_schedule(
            deliverable_code=code,
            included_task_groups=included,
            complexity=p.complexity, tier=p.tier,
            use_slack=p.use_slack,
            slack_after_internal=p.slack_after_internal,
            slack_after_client=p.slack_after_client,
            slack_global_pct=p.slack_global_pct,
            project_start=start_for_this,
            scenario_letter=letter
        )

        if sched:
            d_start = sched[0]["start_date"]
            d_end   = sched[-1]["end_date"]
            d_days  = sum(int(r["duration_days"]) for r in sched)
            y, m, d = map(int, d_end.split("-"))
            cursor_date = datetime.date(y, m, d) + datetime.timedelta(days=1)
        else:
            d_start = d_end = start_for_this
            d_days  = 0

        base = prev_by_code.get(str(code), {"deliverable_code": code})
        base.update({
            "schedule": sched,
            "start": d_start,
            "end": d_end,
            "duration_days": d_days,
        })
        items.append(base)

    # Persist on scenario
    scen["items"] = items
    scen["project_start"] = base_start
    scen["user_order"] = order_codes
    scen["ai_order"] = scen.get("ai_order") or list(order_codes)
    scen["manual_order_locked"] = True
    _CURRENT_SCENARIOS[letter] = scen

    # Return both for convenience
    return {
        "items": [
            {
                "deliverable_code": it["deliverable_code"],
                "start": it["start"], "end": it["end"],
                "duration_days": it["duration_days"],
                "schedule": it["schedule"],
            } for it in items
        ],
        "scenario": scen,
    }


Why this matters
Your current first-registered version returns only {"items": ...} and never sets manual_order_locked, so /api/build is free to re‑sort on the next refresh.
The version above mirrors the later (correct) one you already have that sets user_order and manual_order_locked = True, but makes it the only handler for that path so it’s actually used.

What to change in the UI (1 minute check)

Make sure your “Save Order” button does not immediately rebuild from scratch in a way that discards the server state. After the POST to /api/reorder_timeline, update local state with the returned scenario (or its items) so the table reflects the persisted order:

// pseudo React
const saveOrder = async () => {
  const payload = {
    scenario_letter: activeLetter,
    deliverable_codes: rows.map(r => r.deliverable_code),
    included_map, complexity, tier, use_slack,
    slack_after_internal, slack_after_client, slack_global_pct,
    project_start
  };
  const res = await fetch("/api/reorder_timeline", {
    method: "POST",
    headers: {"Content-Type":"application/json"},
    body: JSON.stringify(payload)
  }).then(r => r.json());

  setScenarios(prev => ({
    ...prev,
    [activeLetter]: res.scenario ? res.scenario : { ...(prev[activeLetter] || {}), items: res.items }
  }));
};


Even if your UI does call /api/build after saving, the server will now keep the order because it sets manual_order_locked = True during Save Order, and /api/build respects it.
