🔧 2‑line hotfix (keeps old code working)

Add this once near the top of your app.js (after window.appState is created), or anywhere that runs on page load:

window.appState = window.appState || {};
Object.defineProperty(window, 'latestScenarios', {
  get() { return window.appState.scenarios; },
  set(v) { window.appState.scenarios = v; }
});


This creates a live alias so any old code that reads/writes latestScenarios will transparently use appState.scenarios.

✅ Make sure the Build step actually sets it

Inside your Build Scenarios A & B function (the handler that calls /api/build), assign the response to the canonical state (and the legacy alias for good measure):

const res = await fetch('/api/build', { method: 'POST', headers: {'Content-Type':'application/json'}, body: JSON.stringify(payload) })
  .then(r => r.json());

window.appState = window.appState || {};
appState.scenarios = res;      // canonical
window.latestScenarios = res;  // legacy alias (works with older code)


Tip: do this right after you successfully receive the JSON, before you render Scenario A/B or enable Export buttons.

🧼 (Optional) Clean replacement instead of alias

If you prefer to remove the alias later, search the front‑end for latestScenarios and replace with appState.scenarios. Typical places:

Export handlers

Timeline renderer (if any)

Any preview cards that show scenario totals

Example safe read:

const scenA = appState.scenarios?.A;
const scenB = appState.scenarios?.B;

🛡️ Guard your export buttons (prevents silent fails)

In your export click handlers, keep a defensive check so you never get the “No deliverables selected” alert after a successful build:

function getScenario(letter) {
  return (window.appState?.scenarios || window.latestScenarios || {})[letter] || null;
}

async function onExport(letter) {
  const scen = getScenario(letter);
  if (!scen || !scen.items || !scen.items.length) {
    alert('Build scenarios first in Step 3.');
    return;
  }
  // ... post to /api/export and download blob ...
}
